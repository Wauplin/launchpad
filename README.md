# Launchpad

Use the sun/moon button beside **Settings** at the bottom left to switch themes. The choice is saved in this browser or desktop webview on this device and survives reloads; other devices keep their own choice. New browser profiles start in light mode. The theme also covers agent summaries, GitHub Markdown, diffs, syntax colors and integrated terminals.

Launchpad is a personal desktop app for Linux (primary target), macOS and Windows that launches and drives coding agents (Claude Code, Codex and OpenCode) and replaces the parts of GitHub used every day: notifications, issues, pull requests and reviews. Everything GitHub-related is cached locally, so moving between items never reloads a page. Launchpad also keeps pre-draft PRs: pull requests that exist only on the laptop until they are worth publishing. A read-only code viewer shows the files of projects, worktrees and branches, and turns selected lines into context for an agent.

The code viewer falls back to plain text above 100 Ki characters, 10,000 lines or 2,000 characters in a line, and disables rendered previews for these files. Highlighting that stalls for five seconds is terminated so later files can still get colors. Files above 5 MB, 100,000 lines or 20,000 characters in a line are refused with an explanation.

Open web URLs in integrated terminals with Ctrl-click (Cmd-click on macOS). Hover to see the destination. On touch devices, tap a link and choose **Open link**; links open in the browser on the device you are using.

The New agent composer accepts file and image attachments from its paperclip button or drag and drop, and screenshots pasted into the prompt. Use Ctrl+V (Cmd+V on macOS) in either the launch prompt or a session message box to attach a clipboard screenshot. The Linux desktop shell reads the system clipboard when WebKitGTK omits image files from the paste event. Attachments show removable previews before launch; limits are eight files, 5 MB each and 20 MB total. Images are sent as native image input, while other files are saved locally for the agent to read. Unsent attachments survive closing the composer and restarting the app.

Settings → **Analytics** shows a calendar of observed weekly quota resets for Claude and Codex alongside their next expected reset dates. History persists across restarts and detects usage drops independently of predictions, including early resets. Tracking starts with this version; detection intervals are shown because resets between readings cannot be timed exactly.

Claude Code and Codex launch with **Allow paid usage** unchecked by default. Launchpad pauses protected sessions when either included subscription quota is reported exhausted, groups them under **Quota paused**, and automatically continues the same conversation once fresh readings confirm capacity in both windows. **Stop** cancels that continuation into Done; **Resume with paid usage** permits additional credits for the session. **Retry with subscription only** resumes a paused session without enabling paid usage when quota readings fail, but can still incur paid credits if the included quota remains exhausted. Claude usage polling runs every three minutes for protected sessions and backs off for repeated HTTP 429 responses; when the OAuth token has expired or the direct call fails, Launchpad asks Claude Code for the same usage data (no model request), so paused sessions still continue once quota is back. A session with paid usage on shows a **Paid usage on** badge in its header; **Use subscription only** puts it back under quota protection, and Summary → Run can allow paid usage again. This is best effort: delayed quota readings and interrupts can allow some paid usage, and unknown readings permit manual work with a notice. External terminal sessions are outside the guard. Pauses survive restart; uncertain continuation claims require manual attention. The model and effort of a launched agent can be changed from the model · effort button in its Summary; Claude agents restart with `--resume` to apply it. AI title generation skipped or cancelled by quota remains pending and retries when the session resumes with available quota or paid usage allowed; manual title edits cancel pending naming.

Codex sessions stay **Background** while commands outlive their completed turn, including headless test browsers. Their command cards remain pending until the actual completion arrives; background output does not change the session to Working. Codex cannot interrupt these commands after the turn ends: close the test process or ask the agent to close it.

OpenCode runs through its native `opencode acp` interface and uses its own configuration/authentication. Launchpad supports native resume, model selection, streamed tools/messages, permission cards and integrated terminal handoff. OpenCode follow-ups wait for the current turn to finish. Its subscription quotas are not monitored by Launchpad; reported USD cost supports a best-effort session cost limit. Pi remains deferred. New harnesses are registered in one Rust module and the registry list; see [the adapter guide](docs/HARNESS_ADAPTERS.md).

Scheduled launches waiting for agents to be Done also accept agents archived after completing their turn. The dependency list shows **Archived · Done** or **Archived · unfinished**; archiving stopped, failed or interrupted work does not satisfy the condition. Completion survives daemon restarts, including existing archived sessions with recorded status history.

Idle sessions offer **Follow up** beside their primary action, including Done, Stopped, Interrupted, Failed, Archived and Quota paused. Clicking it immediately opens the composer with a blank prompt, replacing any existing unsent draft. It prepares a separate session in the same worktree or folder with the saved trace as context when available. Choose the agent/model and click Launch. The original session keeps its state, including automatic quota continuation until you stop it. Pre-draft follow-ups use the existing local PR and its publication checks.

Settings → Harnesses defines named local variants with environment overrides, default model/effort and subscription or pay-as-you-go billing. Variants share the base harness icon and appear in the composer. Subscription variants must use the account monitored by the base harness; alternate accounts should use PAYG mode, which bypasses that quota guard. Claude Code and OpenCode support an optional USD cost limit in the composer and session Summary, with progress in the session header. Reaching reported cost blocks new input and interrupts an active turn best effort; Claude reports cost at turn end, so this is not a hard spending cap. Codex does not report USD costs and cannot enforce a cost limit. PAYG and cost-limited sessions keep a prompt-based title to avoid unaccounted naming requests. Environment values live only in config.toml; sessions reference the variant ID. New variant ▾ offers templates (Claude Code · Hugging Face, another Claude or Codex account, Anthropic API key), and Add variable ▾ lists the documented Claude Code and Codex variables with descriptions, defaults and examples; credentials stay masked until shown. Values may use `${NAME}` (login shell variable of this computer; `${HF_TOKEN}` also reads the `hf auth login` token) and `${LAUNCHPAD_MODEL}` (the session model). The Hugging Face template routes Claude Code to Hugging Face Inference Providers like the `hf claude` extension: its model list (`https://router.huggingface.co/v1/models`, models with tool use only) replaces the Claude models in the composer and every Claude model alias resolves to the chosen model. See [the scope and acceptance check](docs/harness-variants-plan.md).

Sessions with delegated work show a compact **Subagents** control: inspect running/completed agents, expand their nested agents and open each read-only trace without mixing child messages into the parent conversation. Child traces persist with the session. Codex uses native thread ancestry, Claude uses its streamed delegation IDs, and OpenCode uses its native ACP child-session extension when available. Older OpenCode versions expose the delegation prompt and result with a clear notice that inner trace events are unavailable. Parent controls remain responsible for input, Stop and resume; child activity participates in busy checks. See [scope and acceptance](docs/subagents-plan.md).

Automated worktree merge-conflict follow-ups ask the agent to carry the original task results into its new final message, alongside recovery checks and the requested merge status.

## Trusted remote access and pairing

Device pairing automatically discovers matching Tailscale HTTPS routes and offers setup inside Pair a device. For a different private reverse proxy, configure the externally visible origin in `~/.config/launchpad/config.toml` (`launchpad-dev` for dev), then restart that daemon when no agents or terminals are running:

```toml
[server]
bind = "127.0.0.1"
public_origin = "https://launchpad.example.com"
```

With no `public_origin`, Launchpad discovers a running Tailscale node and its Serve configuration at daemon startup (`tailscale status --json` and `tailscale serve status --json`). Pairing prefers the node’s private HTTPS Serve URL when its root route proxies to this daemon’s loopback port. It checks the exact port, so a dev Serve route is never used for production, and skips public Funnel routes or conflicting Launchpad path handlers. Without a matching HTTPS route, Launchpad adds a listener on its own tailnet IP, keeping loopback for the desktop and CLI. Settings → Devices and `launchpad pair` / `url` use the selected origin. Discovery prefers IPv4, falls back to IPv6, and never opens a LAN/public interface. Set `auto_tailnet = false` to disable discovery. An explicit `public_origin` always takes precedence; keep the default loopback listener when an HTTPS gateway runs on the same host. For a custom network address, set `bind` to a reachable interface (or `0.0.0.0`) and `public_origin` to the exact HTTP(S) origin including a non-default port. CLI and desktop tools connect through loopback, so the listener must still accept loopback connections. The tailnet or gateway is the access boundary: every paired browser has full Launchpad access, with no roles or separate permissions.

Forward `/`, `/api/*`, `/ws`, and `/api/terminals/*/ws` to `http://127.0.0.1:7317` (7318 for dev); preserve the external `Host` and browser `Origin`, support WebSocket upgrades and long-lived connections. Serve Launchpad at the origin root, without a URL prefix. Forwarded headers never expand the allowlist or choose cookie security. A proxy may retain the upstream loopback Host while preserving Origin; the configured HTTPS Host or Origin enables `Secure` on the browser cookie.

Run `launchpad pair` on the host to show a QR code and a single-use link, valid for five minutes. Scan it on your phone or open it in another browser, enter a device name and click **Pair browser**. `launchpad url` prints the same kind of link without the terminal QR. Settings → Devices also creates links, shows the full generated URL beside a Copy URL button with copy confirmation, lists browsers and offers **Revoke** (or **Sign out** for the current browser). Revocation disconnects existing event and terminal viewers but keeps agents and PTYs running. Browser credentials last one year and survive daemon restarts; pending pairing links do not. Pairing codes use URL fragments, are removed from the address bar immediately, and are exchanged by POST. The permanent token remains only for CLI/agent bearer requests; old raw-token browser cookies must be paired again. The local desktop shell pairs automatically and reuses an existing valid browser session. Settings → Devices keeps the current desktop app connected instead of offering Sign out. If its credential is revoked from another browser or expires, click **Reconnect to this machine** on the desktop sign-in page; no QR code or device name is needed. With an older installed version, run `launchpad-desktop --quit` and open Launchpad again to pair it automatically; this restarts only the shell and keeps agents and terminals running.

Reverse pairing: on an unpaired browser, enter a device name and choose **Show pairing code**. In a signed-in browser, open Settings → Devices, enter the eight-character code, check the browser name, and click **Approve browser**. Only approve a code visible on your own device: approval grants full Launchpad access. Codes expire after five minutes and work once; only the requesting tab can collect approval. Keep that tab open. The tab must already be able to reach the daemon; use HTTPS for remote access.

If no reachable tailnet address is discovered or configured, pairing falls back to `127.0.0.1` and shows a local-only warning. When Tailscale is installed, Settings → Devices shows HTTPS controls inside **Pair a device**. Choose the suggested unused HTTPS port and click **Run command**: Launchpad executes a fixed `tailscale serve --bg` root proxy for this daemon, preserving other routes and rejecting Funnel-enabled ports. Tailscale manages the certificate; any approval link and command output appear in the same section. Successful setup saves the verified HTTPS origin and immediately updates the QR code and full pairing URL, with no daemon restart or agent interruption. **Update HTTPS URL** checks a manually configured route or setup awaiting approval without re-running the command. **Copy command** remains available. Tailscale controls are absent when its CLI is not installed; paired browsers can run the same explicit setup action on the host. An explicit HTTPS `public_origin` also remains supported for other private gateways.

Manual `[server]` file edits require restart. The explicit Tailscale pairing action can save and activate its verified HTTPS origin live. When an external origin is configured or discovered, `[commands]` remains file-only. Harness variant templates and environment overrides are editable in every paired browser, including with Tailscale access. Other Launchpad settings remain editable in the browser. Browser tabs open external links and new workspaces locally, and Settings → Devices turns on Web Push per browser (HTTPS or `http://127.0.0.1` only; on iOS, add Launchpad to the Home Screen first).

## Install

```sh
packaging/install.sh            # build in release mode, install for the current user, restart the daemon
```

It installs `~/.local/bin/launchpad` and `~/.local/bin/launchpad-desktop`, the systemd user unit `launchpad.service`, the `Launchpad` application entry with its icon, and an autostart entry that keeps the window loaded in the background. Open Launchpad from the applications grid, then right click its dock icon and choose "Add to Favorites". Closing the window only hides it, so the next click shows it at once; `launchpad-desktop --quit` stops it. `launchpad-desktop --new-window --workspace <name>` opens another window on a workspace (the Open in new window menu in the top bar does the same); extra windows close for real. Running the script again updates everything; it asks first when agent sessions are running, because restarting the daemon interrupts them (`--force` skips the question). Launchpad updates are installed manually; there is no in-app updater or installation reservation.

Logs: `journalctl --user -u launchpad -f`.

On a headless Linux server, `packaging/install.sh --headless` installs only the daemon and CLI with the systemd unit, enables lingering so it starts at boot, and skips the desktop shell. Put Tailscale Serve or an identity-aware proxy in front; see [docs/server-hosting.md](docs/server-hosting.md) for the setup, the first-run sign-in checklist and operations.

The app uses the sculpted launch icon, also shown in the top-left corner of the UI. Its master and PNG/WebP exports are in [packaging/icons](packaging/icons/README.md); the SVG wraps the raster artwork. Use `packaging/install-icons.sh` to update only the installed icon without restarting the app or daemon. Regenerate exports with `python3 packaging/generate-icons.py` (requires Pillow).

Presets are entirely user-defined; Launchpad ships none and defaults to an empty list. Existing saved presets are preserved. All saved presets in Settings are available in the agent composer, in the same order. Presets add instructions to the prompt; use Run in → Pre-draft PR or New worktree for Launchpad-managed folders. Changing Run in keeps your selected presets.

## Development

Requirements: Rust 1.93 or later, Node 24 (`nvm use` in `web/`, which has an `.nvmrc`), pnpm 10 (pinned in `web/package.json`; Corepack picks it up when pnpm runs from `web/`), and the Tauri system libraries (`libwebkit2gtk-4.1-dev`, `librsvg2-dev`, `libayatana-appindicator3-dev`, `build-essential`).

```sh
(cd web && pnpm install)
(cd web && pnpm build)                                   # UI into web/dist (served by the daemon)
LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- daemon   # dev daemon on 127.0.0.1:7318
LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- url      # address that signs a browser in
LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- status   # status as JSON
```

- Profiles: `LAUNCHPAD_PROFILE=dev` uses port 7318, `~/.config/launchpad-dev` and `~/.local/share/launchpad-dev`. Without it (prod): port 7317, `~/.config/launchpad`, `~/.local/share/launchpad`.
- A debug build of the daemon reads `web/dist` from disk, so `(cd web && pnpm build)` updates the UI without restarting it. A release build embeds the UI.
- Hot reload: `(cd web && pnpm dev)` serves the UI on http://localhost:5173 and proxies the API to the dev daemon. Sign in once with the address printed by `launchpad url`, with port 5173 instead of 7318.
- GitHub: sign in with `gh auth login` (a token with `repo` or `notifications` scope). The daemon reads the token from `gh auth token`, polls notifications in the background, and keeps cached threads available when offline. GitHub’s public API also returns Done notifications, so Launchpad tracks inbox membership locally and excludes explicitly ignored subscriptions. Its initial inbox contains unread threads; existing read inbox items can be restored from a known GitHub snapshot. Read/Done changes made on github.com cannot be mirrored exactly through this API. Opening an unread thread marks it read on GitHub. Unread is local only; replies post only when you click **Post reply**.
- Pre-draft PRs: choose a project, then **Run in → Pre-draft PR** in the composer. Launchpad fetches `origin`, creates `lp/<slug>` in `<projects_root>/.worktrees/<project-id>/<slug>`, and launches the agent there. Review it from the project PR list or the session’s **Pre-draft PR** button. **Refresh** fetches the base; **Notes** supports general and file feedback, sent to the same session. **Publish** takes a remote branch name and a draft/ready choice, then requires confirmation. Commit all changes before publishing or discarding. Settings → General can remove clean worktrees after publication; the default keeps them.
- Task worktree CLI (used by agents): `launchpad work finish --session-id <id>` and `launchpad work add-project --session-id <id> --project <name>`.
- Local PR CLI: `LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- pr list`. From a pre-draft worktree, use the absolute dev binary (`<checkout>/target/debug/launchpad pr show` or `pr update --title "…" --body-file <file>`) with `LAUNCHPAD_PROFILE=dev`. The installed binary uses production by default. `pr create --title "…" --body-file <file>` copies the current committed HEAD into a dedicated worktree; it preserves the original checkout and returns the new folder as `root`. Its review page offers **Launch agent** to link a session. At startup, the daemon links `skills/launchpad` into `~/.agents/skills/launchpad`, preserving any existing user-owned real directory. Windows uses a managed skill copy that is refreshed on startup.
- Agent suggestions: `launchpad suggest comment --repo owner/repo --number 123 --body-file /path/to/comment.md`; use `suggest review` with `--head <inspected-commit>` and optionally `--event approve|request-changes`. Agents also pass `--session-id` from their prompt for attribution. Use the prompt’s exact binary path and `LAUNCHPAD_PROFILE`. Replace `--repo` and `--number` with `--predraft <id>` for a local PR. These commands only save drafts. Issue/PR conversation cards offer Edit, Post comment/review and Discard; local PR description cards offer Add to local notes. The PR’s **Review with agent** button opens the composer with the displayed head and instructions. A changed PR head blocks a suggested review. An interrupted or failed publication stays visible for inspection and is never automatically retried.
- Agent trace context: the prompt references each attached trace instead of inlining it. Agents print it with `launchpad trace <session-id> --through <seq>` (omit `--through` for the latest stored event), using the exact binary path and `LAUNCHPAD_PROFILE` from their prompt.
- Types shared with the UI are generated from Rust: `cargo run -p launchpad -- gen-types` (writes `web/src/gen/`).
- Desktop window for the dev daemon: `cargo build -p launchpad-desktop && LAUNCHPAD_PROFILE=dev ./target/debug/launchpad-desktop` (a dev window is not single-instance and quits when closed). `--open <route>` opens a given screen, `--workspace <id or name>` starts on a workspace. Each dev process is its own window.
- WebKitGTK benchmark: open `/dev/perf?auto=1` in the window; results go to the daemon log ([spike 4](docs/spikes/4-webkitgtk.md)).
- Code viewer: Code on a project page, on a worktree or `/projects/<id>/code?root=<folder>&rev=<revision>&path=<file>&line=<n>`. Files come from disk and git (`/api/code/*`); only registered projects and their git worktrees are readable. Colors come from Shiki in a Web Worker, so a file shows as plain text first. Commit hashes (7–40 hex characters) in session Markdown prose and inline code become links only after Git confirms a unique commit in that project; links open that commit’s diff in Launchpad with Back to session, including after session worktree cleanup. Diff is the default, with unified/split patches, a changed-file list and a Diff/Code toggle. Merge commits compare against the first parent; root commits show all additions. View file opens the selected file (the parent revision for deleted files).
- Tests: `cargo test` covers core parsers, native terminal behavior, durable retry operations, and front-door pairing/HTTP/WebSocket checks with isolated state.

## Continuous integration

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on pushes to `main`, pull requests and manual dispatch in `Wauplin/launchpad`. Linux linting checks strict workspace Clippy and UI types. Native **Tests** jobs run on Ubuntu 24.04, macOS 15 and Windows 2025. Native **Build artifacts** jobs use Ubuntu 22.04 for the Linux runtime baseline and build the UI first, both release binaries, run the existing tests in release mode and smoke-test the CLI on Linux x86_64, macOS Apple Silicon and Intel, and Windows x86_64. Rust is pinned to 1.93.1; Node comes from `web/.nvmrc`, pnpm from `web/package.json`, and dependency installs use the lockfiles.

Successful builds upload `launchpad-linux-x86_64`, `launchpad-macos-aarch64`, `launchpad-macos-x86_64` and `launchpad-windows-x86_64`, retained for 90 days. Each contains a tar archive and SHA-256 file. Extract the archive and run `bash packaging/install.sh --prebuilt` on Linux/macOS or `powershell -ExecutionPolicy Bypass -File packaging/install.ps1 -Prebuilt` on Windows. The archive includes `target/release/`, embedded UI, installers, icons, the agent skill and a `COMMIT` manifest. These are continuous builds of commits, not versioned GitHub Releases. Linux targets Ubuntu 22.04 or newer and requires the WebKitGTK 4.1, GTK 3 and appindicator runtime libraries; macOS uses WKWebView; Windows requires WebView2. Builds are currently unsigned and macOS is not notarized.

Run the same checks locally:

```sh
cargo +1.93.1 clippy --workspace --all-targets --locked -- -D warnings
(cd web && pnpm install --frozen-lockfile && pnpm typecheck && pnpm test:attachments && pnpm test:composer && pnpm test:drafts && pnpm test:sessions && pnpm test:markdown && pnpm build)
cargo +1.93.1 test --locked
cargo +1.93.1 build --release --locked -p launchpad -p launchpad-desktop
```

CI runs lint and native Linux/macOS/Windows debug tests on main pushes, pull requests and tags. Release builds, release tests and downloadable binaries run only on tag refs, including manual dispatch on a tag; manual runs on main skip binaries. Linux release builds use Ubuntu 22.04, with macOS ARM64/Intel and Windows x86_64 built natively.

Install the CI toolchain if needed: `rustup toolchain install 1.93.1 --profile minimal --component clippy`.

## macOS and Windows

Linux remains the primary daily-use target. On macOS, `bash packaging/install.sh` builds and installs to `~/.local/bin`, adds launchd login agents and creates `~/Applications/Launchpad.app`. On Windows, `powershell -ExecutionPolicy Bypass -File packaging/install.ps1` builds and installs to `%USERPROFILE%/.local/bin`, adds Start menu and login shortcuts, and adds the binaries to the user PATH. The desktop starts a detached daemon when needed on either platform. Config and data keep the same home-relative `.config/launchpad` and `.local/share/launchpad` layout on all systems. Git, GitHub CLI and the selected agent harness must be installed and on PATH; Windows inherits the login environment, while Unix resolves the login shell. Windows Terminal is the default terminal on Windows; Terminal is the default on macOS. Add `~/.local/bin` to the macOS shell PATH to use the CLI by name.

For source builds, install the [Tauri platform prerequisites](https://v2.tauri.app/start/prerequisites/) (Xcode command-line tools on macOS; MSVC C++ Build Tools and WebView2 on Windows), Rust 1.93.1, Node 24 and Corepack/pnpm. Build the UI before `cargo build --release --locked -p launchpad -p launchpad-desktop`. Native tests use `cargo test --locked` and `cargo test --release --locked`. In PowerShell, set a dev profile with `$env:LAUNCHPAD_PROFILE = 'dev'` before `cargo run -p launchpad -- daemon`.
