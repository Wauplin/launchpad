# Launchpad

Launchpad is a personal desktop app for Linux (primary target), macOS and Windows that launches and drives coding agents (Claude Code, Codex and OpenCode) and replaces the parts of GitHub used every day: notifications, issues, pull requests and reviews. Everything GitHub-related is cached locally, so moving between items never reloads a page. Launchpad also keeps pre-draft PRs: pull requests that exist only on the laptop until they are worth publishing. A read-only code viewer shows the files of projects, worktrees and branches, and turns selected lines into context for an agent.

Claude Code and Codex launch with **Allow paid usage** unchecked by default. Launchpad pauses protected sessions when either included subscription quota is reported exhausted, groups them under **Quota paused**, and automatically continues the same conversation once fresh readings confirm capacity in both windows. **Stop** cancels that continuation into Done; **Resume with paid usage** permits additional credits for the session. A session with paid usage on shows a **Paid usage on** badge in its header; **Use subscription only** puts it back under quota protection, and Summary → Run can allow paid usage again. This is best effort: delayed quota readings and interrupts can allow some paid usage, and unknown readings permit manual work with a notice. External terminal sessions are outside the guard. Pauses survive restart; uncertain continuation claims require manual attention. The model and effort of a launched agent can be changed from the model · effort button in its header or Summary; Claude agents restart with `--resume` to apply it. AI title generation skipped or cancelled by quota remains pending and retries when the session resumes with available quota or paid usage allowed; manual title edits cancel pending naming.

OpenCode runs through its native `opencode acp` interface and uses its own configuration/authentication. Launchpad supports native resume, model selection, streamed tools/messages, permission cards and integrated terminal handoff. OpenCode follow-ups wait for the current turn to finish. Its subscription quotas are not monitored by Launchpad; reported USD cost supports a best-effort session cost limit. SSH and Pi remain deferred. New harnesses are registered in one Rust module and the registry list; see [the adapter guide](docs/HARNESS_ADAPTERS.md).

Settings → Harnesses defines named local variants with environment overrides, default model/effort and subscription or pay-as-you-go billing. Variants share the base harness icon and appear in the composer. Subscription variants must use the account monitored by the base harness; alternate accounts should use PAYG mode, which bypasses that quota guard. Claude Code and OpenCode support an optional USD cost limit in the composer and session Summary, with progress in the session header. Reaching reported cost blocks new input and interrupts an active turn best effort; Claude reports cost at turn end, so this is not a hard spending cap. Codex does not report USD costs and cannot enforce a cost limit. PAYG and cost-limited sessions keep a prompt-based title to avoid unaccounted naming requests. Environment values live only in config.toml; sessions reference the variant ID. See [the scope and acceptance check](docs/harness-variants-plan.md).

Phase 0 (foundations and spikes) is done: the daemon runs as a systemd user service, the window opens from the dock, and the status bar shows registered harness versions and supported subscription quotas, plus the running Launchpad commit. Launchpad updates are installed manually. Phase 1 (launch and run agents) is built and awaiting its week of daily use. Registered project remote URLs and GitHub mappings refresh from local Git configuration on reads and every 30 seconds, including in already open windows. Phase 2 (GitHub inbox) is built and awaiting a morning of notification triage: cached notifications, repo filters, thread summaries, quick replies, triage actions and agent launch from a thread. Agent launches open the composer directly and remember the last launched harness, model and effort. The refresh icon beside the Model field or Refresh models inside its menu queries the selected harness immediately. The launcher can start now, after a duration, at a local date and time, when selected running or scheduled agents are all Done, or at a reported Claude/Codex quota reset. Delayed launches persist locally and appear under Scheduled in Agents, with Start now and Cancel controls. Non-running sessions open a summary of recorded run facts, the initial task, exact last message and factual next steps; the full trace remains one click away. Schedule follow-up sends a saved message to the same session using the existing start conditions, with Cancel in Scheduled and the summary. Cron agents repeat a launch on a 5-field cron schedule when their conditions hold (previous run finished, quota left) and appear under Cron in Agents. Sessions support pasted and dropped images, AI-generated prompt-based titles, and independently collapsible Cron/Scheduled/Running/Quota paused/Stopped/Interrupted/Failed/In terminal/Done/Archived groups (empty groups hidden) with remembered expansion state and sidebar activity indicators. Archived contains only explicitly archived sessions. Closing a session panel keeps its state; a separate Archive button archives the resumable conversation. The light UI has stronger contrast and defaults to 120% zoom; Settings → General offers five zoom sizes. Phase 2b (code viewer) is built and awaiting its week of daily use: a project's checkout, worktrees, branches, tags and fetched PR heads, with a file tree, change letters and line bars, tabs, colors, Markdown and static HTML previews, find in file (`Ctrl+F`), search in the project, and selected lines sent to the composer or a session. Phase 3 (issues and pull requests) is built and awaiting daily review and merge checks: full cached conversations, reviews, check links, reviewers, labels, issue state controls, PR draft and merge controls, project issue/PR lists with colored GitHub labels, label filtering and multi-select launch, and virtualized unified/split diffs with viewed markers and full-file navigation. Phase 4 (pre-draft PRs) is built and awaiting two weeks of daily use: dedicated local branches and worktrees, agent-facing CLI commands, teal project PR rows, descriptions, commits and diffs, saved general/file review notes, feedback to the same session, and explicit draft/ready publication with a reviewed commit check. Phase 5 (workspace polish) is built and awaiting daily use: workspaces (named sets of projects that narrow agents, projects and the inbox, switched per window with visible one-click workspace buttons beside the Launchpad brand on the left of the single-row top bar and managed in Settings → Workspaces; All workspaces shows every project and combines sidebar folders from every workspace with explicitly pinned projects, with New window to show another workspace in parallel and an All repos button in the inbox), one selected agent panel per window with the selection remembered per workspace, persistent pins toggled by a star beside the title, inline title editing and session/message search, explicit Claude/Codex history import with native resume, a read-only per-session Git panel and Open in editor, and recent composer context chips. The composer’s **Agent trace** picker and each session’s **Add trace as context** button attach a previous conversation and its tool activity through a fixed stored event; the prompt preview shows the included trace. Phase 6 (agent-written suggestions) is built and awaiting daily posting checks: local comment/review drafts from the CLI, editable teal cards, a PR Review with agent action, and explicit publication tied to the reviewed commit. The owner-approved harness registration refactor and OpenCode integration are built. Other Phase 7 candidates remain deferred: session workers, embedded terminal and remote browser mode were reverted on 2026-10-03 because the phase needed a clearer scope. Restarting the daemon interrupts running turns; native Resume and the integrated terminal dock remain available. See [docs/ROADMAP.md](docs/ROADMAP.md).

Integrated terminals (scoped Phase 7a, built and awaiting daily use) run shells and a registered harness TUI in a bottom dock: open one from a project, a worktree, a session, a pre-draft or the code viewer, or with the Terminal button in the status bar. "Open in terminal" now uses this dock instead of an external terminal window. The daemon owns the terminal processes, so restarting it ends them.

Project pages show Running agents, GitHub pull requests/issues, Worktrees, then All agents (including running sessions). Empty GitHub tabs shrink to their message.

## Install

```sh
packaging/install.sh            # build in release mode, install for the current user, restart the daemon
```

It installs `~/.local/bin/launchpad` and `~/.local/bin/launchpad-desktop`, the systemd user unit `launchpad.service`, the `Launchpad` application entry with its icon, and an autostart entry that keeps the window loaded in the background. Open Launchpad from the applications grid, then right click its dock icon and choose "Add to Favorites". Closing the window only hides it, so the next click shows it at once; `launchpad-desktop --quit` stops it. `launchpad-desktop --new-window --workspace <name>` opens another window on a workspace (the workspace buttons in the top bar have the same New window buttons); extra windows close for real. Running the script again updates everything; it asks first when agent sessions are running, because restarting the daemon interrupts them (`--force` skips the question). Launchpad updates are installed manually; there is no in-app updater or installation reservation.

Logs: `journalctl --user -u launchpad -f`.

The app uses the sculpted launch icon, also shown in the top-left corner of the UI. Its master and PNG/WebP exports are in [packaging/icons](packaging/icons/README.md); the SVG wraps the raster artwork. Use `packaging/install-icons.sh` to update only the installed icon without restarting the app or daemon. Regenerate exports with `python3 packaging/generate-icons.py` (requires Pillow).

## Development

Requirements: Rust 1.93 or later, Node 24 (`nvm use` in `web/`, which has an `.nvmrc`), pnpm 10 (pinned in `web/package.json`; Corepack picks it up when pnpm runs from `web/`), and the Tauri system libraries (`libwebkit2gtk-4.1-dev`, `librsvg2-dev`, `libayatana-appindicator3-dev`, `build-essential`).

```sh
(cd web && pnpm install)
(cd web && pnpm build)                                   # UI into web/dist (served by the daemon)
LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- daemon   # dev daemon on 127.0.0.1:7318
LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- url      # address that signs a browser in
LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- status   # status as JSON
```

- Profiles: `LAUNCHPAD_PROFILE=dev` uses port 7318, `~/.config/launchpad-dev` and `~/.local/share/launchpad-dev`. Without it (prod): port 7317, `~/.config/launchpad`, `~/.local/share/launchpad`.
- A debug build of the daemon reads `web/dist` from disk, so `(cd web && pnpm build)` updates the UI without restarting it. A release build embeds the UI.
- Hot reload: `(cd web && pnpm dev)` serves the UI on http://localhost:5173 and proxies the API to the dev daemon. Sign in once with the address printed by `launchpad url`, with port 5173 instead of 7318.
- GitHub: sign in with `gh auth login` (a token with `repo` or `notifications` scope). The daemon reads the token from `gh auth token`, polls notifications in the background, and keeps cached threads available when offline. GitHub’s public API also returns Done notifications, so Launchpad tracks inbox membership locally and excludes explicitly ignored subscriptions. Its initial inbox contains unread threads; existing read inbox items can be restored from a known GitHub snapshot. Read/Done changes made on github.com cannot be mirrored exactly through this API. Opening an unread thread marks it read on GitHub. Unread is local only; replies post only when you click **Post reply**.
- Pre-draft PRs: choose a project, then **Run in → Pre-draft PR** in the composer. Launchpad fetches `origin`, creates `lp/<slug>` in `<projects_root>/.worktrees/<project-id>/<slug>`, and launches the agent there. Review it from the project PR list or the session’s **Pre-draft PR** button. **Refresh** fetches the base; **Notes** supports general and file feedback, sent to the same session. **Publish** takes a remote branch name and a draft/ready choice, then requires confirmation. Commit all changes before publishing or discarding. Settings → General can remove clean worktrees after publication; the default keeps them.
- Local PR CLI: `LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- pr list`. From a pre-draft worktree, use the absolute dev binary (`<checkout>/target/debug/launchpad pr show` or `pr update --title "…" --body-file <file>`) with `LAUNCHPAD_PROFILE=dev`. The installed binary uses production by default. `pr create --title "…" --body-file <file>` copies the current committed HEAD into a dedicated worktree; it preserves the original checkout and returns the new folder as `root`. Its review page offers **Launch agent** to link a session. At startup, the daemon links `skills/launchpad` into `~/.agents/skills/launchpad`, preserving any existing user-owned real directory. Windows uses a managed skill copy that is refreshed on startup.
- Agent suggestions: `launchpad suggest comment --repo owner/repo --number 123 --body-file /path/to/comment.md`; use `suggest review` with `--head <inspected-commit>` and optionally `--event approve|request-changes`. Agents also pass `--session-id` from their prompt for attribution. Use the prompt’s exact binary path and `LAUNCHPAD_PROFILE`. Replace `--repo` and `--number` with `--predraft <id>` for a local PR. These commands only save drafts. Issue/PR conversation cards offer Edit, Post comment/review and Discard; local PR description cards offer Add to local notes. The PR’s **Review with agent** button opens the composer with the displayed head and instructions. A changed PR head blocks a suggested review. An interrupted or failed publication stays visible for inspection and is never automatically retried.
- Agent trace context: the prompt references each attached trace instead of inlining it. Agents print it with `launchpad trace <session-id> --through <seq>` (omit `--through` for the latest stored event), using the exact binary path and `LAUNCHPAD_PROFILE` from their prompt.
- Types shared with the UI are generated from Rust: `cargo run -p launchpad -- gen-types` (writes `web/src/gen/`).
- Desktop window for the dev daemon: `cargo build -p launchpad-desktop && LAUNCHPAD_PROFILE=dev ./target/debug/launchpad-desktop` (a dev window is not single-instance and quits when closed). `--open <route>` opens a given screen, `--workspace <id or name>` starts on a workspace. Each dev process is its own window.
- WebKitGTK benchmark: open `/dev/perf?auto=1` in the window; results go to the daemon log ([spike 4](docs/spikes/4-webkitgtk.md)).
- Code viewer: Code on a project page, on a worktree or `/projects/<id>/code?root=<folder>&rev=<revision>&path=<file>&line=<n>`. Files come from disk and git (`/api/code/*`); only registered projects and their git worktrees are readable. Colors come from Shiki in a Web Worker, so a file shows as plain text first.
- Tests: `cargo test` (a few pure functions: the prompt renderer, the remote and link parsers, the code viewer's diff hunk, path and `git grep` parsers). It runs in well under a second once built.

## Continuous integration

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on pushes to `main`, pull requests and manual dispatch in `Wauplin/launchpad`. Linux linting checks strict workspace Clippy and UI types. Native **Tests** jobs run on Ubuntu 24.04, macOS 15 and Windows 2025. Native **Build artifacts** jobs use Ubuntu 22.04 for the Linux runtime baseline and build the UI first, both release binaries, run the existing tests in release mode and smoke-test the CLI on Linux x86_64, macOS Apple Silicon and Intel, and Windows x86_64. Rust is pinned to 1.93.1; Node comes from `web/.nvmrc`, pnpm from `web/package.json`, and dependency installs use the lockfiles.

Successful builds upload `launchpad-linux-x86_64`, `launchpad-macos-aarch64`, `launchpad-macos-x86_64` and `launchpad-windows-x86_64`, retained for 90 days. Each contains a tar archive and SHA-256 file. Extract the archive and run `bash packaging/install.sh --prebuilt` on Linux/macOS or `powershell -ExecutionPolicy Bypass -File packaging/install.ps1 -Prebuilt` on Windows. The archive includes `target/release/`, embedded UI, installers, icons, the agent skill and a `COMMIT` manifest. These are continuous builds of commits, not versioned GitHub Releases. Linux targets Ubuntu 22.04 or newer and requires the WebKitGTK 4.1, GTK 3 and appindicator runtime libraries; macOS uses WKWebView; Windows requires WebView2. Builds are currently unsigned and macOS is not notarized.

Run the same checks locally:

```sh
cargo +1.93.1 clippy --workspace --all-targets --locked -- -D warnings
(cd web && pnpm install --frozen-lockfile && pnpm typecheck && pnpm build)
cargo +1.93.1 test --locked
cargo +1.93.1 build --release --locked -p launchpad -p launchpad-desktop
```

CI runs lint and native Linux/macOS/Windows debug tests on main pushes, pull requests and tags. Release builds, release tests and downloadable binaries run only on tag refs, including manual dispatch on a tag; manual runs on main skip binaries. Linux release builds use Ubuntu 22.04, with macOS ARM64/Intel and Windows x86_64 built natively.

Install the CI toolchain if needed: `rustup toolchain install 1.93.1 --profile minimal --component clippy`.

## macOS and Windows

Linux remains the primary daily-use target. On macOS, `bash packaging/install.sh` builds and installs to `~/.local/bin`, adds launchd login agents and creates `~/Applications/Launchpad.app`. On Windows, `powershell -ExecutionPolicy Bypass -File packaging/install.ps1` builds and installs to `%USERPROFILE%/.local/bin`, adds Start menu and login shortcuts, and adds the binaries to the user PATH. The desktop starts a detached daemon when needed on either platform. Config and data keep the same home-relative `.config/launchpad` and `.local/share/launchpad` layout on all systems. Git, GitHub CLI and the selected agent harness must be installed and on PATH; Windows inherits the login environment, while Unix resolves the login shell. Windows Terminal is the default terminal on Windows; Terminal is the default on macOS. Add `~/.local/bin` to the macOS shell PATH to use the CLI by name.

For source builds, install the [Tauri platform prerequisites](https://v2.tauri.app/start/prerequisites/) (Xcode command-line tools on macOS; MSVC C++ Build Tools and WebView2 on Windows), Rust 1.93.1, Node 24 and Corepack/pnpm. Build the UI before `cargo build --release --locked -p launchpad -p launchpad-desktop`. Native tests use `cargo test --locked` and `cargo test --release --locked`. In PowerShell, set a dev profile with `$env:LAUNCHPAD_PROFILE = 'dev'` before `cargo run -p launchpad -- daemon`.
