# Implementation and acceptance

Source: [technical report revision 3](https://wauplin-launchpad-spaces-technical-report.static.hf.space), reference trace `24f6f408-46f8-4d67-9bc9-195f7c810a0f` through event 128. The owner's 2026-10-31 follow-up overrides its visibility gate: protected Spaces are accepted as private until the Hub API is fixed. This implementation no longer blocks on that distinction.

## Implemented

- P0/P1: startup-only Space/bucket metadata checks, explicit protected compatibility, exact Host/Origin and adapter CSRF guards, streaming HTTP and both WebSockets, stripped caller identity, blocked pairing/device/push/desktop/setup-terminal routes, preserved loopback bearer/Ask restrictions, separate control/agent UIDs and allowlisted environments.
- P2: generic trace prefix and process-pinned destination; schema-bound config/SQLite credential projection; provider, per-profile, SSH and relevant Git credential roots; plaintext ordinary archives/native resume snapshots; authenticated vault generations, file-event/reconciliation observation, deletion persistence, read-back/manifest-last commits, restore validation, reconnect recovery and no automatic pruning.
- P3: private bucket creation and key bootstrap with restart-safe HF Secret injection; copy-once fallback; ephemeral pinned CLI login processes for Codex, Claude, OpenCode and gh; masked read-only-validated API/HF tokens, a core-provided HF inference profile for HF-account-only setup; profile creation through existing APIs; HTTPS Git setup; SSH generation/import; bounded authorization buffers and cancellation; compact responsive controls plus native app setup links.
- P4: pinned headless Docker build, recorded dependency inventory, minimal immutable duplicate template, release workflow and optional HF template publishing, independent adapter/tool versions, conditional update discovery, expected-parent image update, idle/checkpoint interlocks, image-plus-data rollback, one-shot restore acknowledgment, planned encryption-key rotation and uncertain-operation records. Maintenance pauses/drains the backup writer; credential timestamps prevent stale generations from replacing a newer checkpoint.

## Local evidence

The full Docker runtime built successfully. Manual checks use an isolated, network-disabled task container, synthetic secrets and throwaway Git data; they do not change the host or cloud account configuration. The real daemon served delegated capability metadata, accepted proxied HTTP with attacker-supplied Authorization stripped/replaced, rejected missing browser Origin, upgraded bus and terminal WebSockets, and retained the restricted Ask token's denial of config access. The terminal opened for this check was closed.

A synthetic repository deliberately committed a credential filename. Capture sealed its relevant Git history and credential file, kept them out of the ordinary archive, round-tripped the vault, restored files/Git state/executable modes and restarted the real daemon successfully. The check also found Codex's transient external symlinks; those CLI temp/debug roots are now excluded. No agent processes remained after the check. The agent UID could not read the root process environment or control-plane directory.

Pinned Python dependency checks passed for config/SQLite splitting and rejoining, removal of secret bytes from the materialized database, preservation of numeric token counts and authenticated credential envelopes. Python compilation, shell JavaScript syntax, release-workflow YAML parsing, UI typecheck/production build, existing trace regressions and tour/demo guardrails are part of validation. No new unit tests were added. A read-only authenticated HF check accepted the protected report Space and rejected a deliberately absent bucket; it created or changed no resource.

## Live acceptance still required

Publish the branch/release through the owner's normal workflow, configure the optional public template publisher, and deploy a dedicated Space/bucket before performing cloud checks. This task does not push or publish its branch, provision paid hardware, authorize real providers or mutate production.

Exercise actual HF ingress on Hub/direct URLs, collaborators and anonymous visitors under the accepted protected policy; provider browser authorization/expiry/cancel/reconnect; remote bucket restore and corruption/key-loss recovery; secret-mutation restarts; actual image update and rollback; private Hub rendering of Claude/Codex traces (OpenCode viewer support is not claimed); Git/SSH port behavior; and a 24–72 hour paid-CPU/sleep-off soak with schedules, quota/cost stops, bucket outages and forced restarts. Measure upload duration, memory, RPO and RTO rather than treating the configured cadence as a guarantee.

Browser visual and back/forward/keyboard QA needs a connected browser surface; none was available during initial implementation. Responsive CSS and route synchronization are authored, but native phone keyboard and browser history behavior still require device checks. Multiple writers/replicas, a remote replacement for the local Chrome extension, arbitrary outbound SSH port 22, automatic discovery of all secrets in code, and an offline recovery key remain outside scope.
