# Launchpad

Launchpad is a personal desktop app for Linux (primary target), macOS and Windows (Tauri) that launches and drives coding agents (Claude Code, Codex, OpenCode) and replaces the parts of the GitHub UI used every day, with a local cache so nothing feels slow. It has one user, on one machine.

Status: Phase 0 done, Phases 1, 2, 2b, 3, 4, 5 and 6 built and awaiting daily-use checks; the scoped Phase 7 harness registry/OpenCode and profiles/cost-limits steps (profiles with per-login quota monitors and SSH host awareness, 2026-10-22) and Phase 7a integrated terminals are built; the UX suggestions pass (2026-10-11, `docs/research/ux-suggestions/`) and managed agent worktrees (2026-10-11, `docs/managed-worktrees-plan.md`) are built and awaiting daily use; the scoped retry-safe Launch/Send blocker D fix is built; the trusted-network front door and device pairing (2026-10-13) are built and awaiting deployment checks; SSH hosts (Phase 7d, 2026-10-14, `docs/ssh-hosts-plan.md`) are built and awaiting daily use; the Chrome extension redesign with project-linked browser tasks (2026-10-26, `extension/README.md`) is built and awaiting daily use; the UX consistency review (2026-10-27, `docs/glossary.md`, report at https://wauplin-launchpad-ux-consistency-review.static.hf.space) and Ask Launchpad are built and awaiting daily use; onboarding (demo tour and setup checklist, 2026-10-28, `docs/ARCHITECTURE.md` 15.6) is built and awaiting daily use; other candidates are deferred until they have an owner-approved scope (see `docs/ROADMAP.md`). Linux releases use 22.04 so updates run on the primary machine; verify the downloaded CI binary locally before changing that baseline. Release cache keys include the runner image so newer glibc build objects cannot leak into the 22.04 build. Build the UI before the release daemon so it embeds the assets; keep CI commands and toolchain documentation in sync.

The panel (`extension/src/app.tsx`, `compose.tsx`, `task.tsx`, own `x-` styles) is its own small chat UI: never import the app's Composer, SessionPane, router or phone shell into it; reuse only `lib/` helpers, stores' pure helpers, generated types and Markdown. Sending creates the grants of the chosen tabs and launches in one owner click; keep Chrome's permission request first in that click. `Target::Browser { project_id, act }`: without a project, a scratch folder with browser tools only; with one, a task worktree with the harness's normal tools plus `launchpad_browser` (no terminal TUI handoff). `act` makes the task's grants Work grants (`POST /api/browser/sessions/{id}/mode` switches it). Always-allowed sites (`browser_site`, `/api/browser/sites`) only skip navigation site reviews and set the starting mode; consequential actions are always reviewed. A task without a shared tab gets a "New tab" handle (`POST /api/browser/grants/new-tab`, tab -1, always Work): it only accepts browser_navigate/open_tab, opens new tabs in the task's group and keeps per-site reviews; exclude handles from tab conflict checks. - Run the dev daemon: `LAUNCHPAD_ENV=dev cargo run -p launchpad -- daemon` (port 7318, data in `~/.local/share/launchpad-dev`). For an isolated second daemon, set `HOME` to a scratch folder and `LAUNCHPAD_PORT` to a free port (the CLI honors both). - Pair a browser: `LAUNCHPAD_ENV=dev cargo run -p launchpad -- pair` prints a QR code and five-minute single-use link; `url` prints only the link. Settings → Devices creates links, shows the full pairing URL with Copy URL and copy confirmation, and revokes browsers. The desktop shell gets a local pairing link via bearer POST and reuses a valid device cookie. Settings hides Sign out for the current desktop window; the unauthenticated desktop sign-in page offers Reconnect to this machine through the local-origin-only `reconnect_local` Tauri command. Other browsers remain revocable, including a desktop credential from another browser. Restarting only `launchpad-desktop` also repairs pairing without interrupting the daemon.
- Reverse pairing: the unpaired browser can request an eight-character code; Settings → Devices checks it then explicitly approves full access. Five-minute, memory-only requests bind approval to a separate 256-bit tab secret, consumed atomically on collection; never exchange the short code alone for a credential. Bound issuance (5/minute per socket peer, 20/minute globally, 100 pending; proxies share a peer budget and QR/link pairing remains the fallback), authenticated checks/approvals (30/minute), and polling (one per two seconds per request). Keep the requesting tab open; remote access still needs a reachable trusted origin and preferably HTTPS.
- Front door: with no `public_origin`, `[server] auto_tailnet` (default true) discovers a running Tailscale node at startup, preferring a private HTTPS Serve root route exclusively serving this daemon’s loopback port (no other same-origin handlers, including foreground routes); otherwise it adds a listener on its own IP, keeping loopback. Settings → Devices puts Tailscale controls inside Pair a device only when its CLI is installed (`GET /api/devices/pairing-info`). Owner-clicked Run command (`POST /api/devices/https/run`) creates only a fixed private root Serve proxy to this daemon, checking occupied/Funnel ports first; it never runs arbitrary shell input or overwrites another route. Command output/approval links stay in that section; Update HTTPS URL (`POST /api/devices/https/check`) only inspects a matching route. Success persists the validated exact HTTPS origin, atomically updates live Host/Origin/cookie checks and returns a fresh QR/link without restart. Keep loopback and previously allowed viewers working, enable remote file-only command rules immediately, serialize setup actions and bound subprocess output/time. Startup discovery remains read-only; never auto-adopt Funnel, another daemon’s port or conflicting app paths. Pairing uses the selected origin or warns on a local-only fallback. Explicit `public_origin` takes precedence; disable discovery with `auto_tailnet = false`. Discovered tailnet access also makes commands file-only. `[server] bind` defaults to `127.0.0.1`; `public_origin` permits the exact external Host/Origin behind Tailscale or a private proxy. Manual network file edits require restart; owner-clicked Tailscale setup is the narrow exception for a verified HTTPS origin. Preserve external Host/Origin and forward both WebSocket paths; never infer allowed origins or Secure cookies from forwarded headers. Browser device hashes live in `state.db`; pending pairs are memory-only, and revocation disconnects upgraded viewers without stopping host processes. Every paired browser is trusted with full Launchpad access. With `public_origin`, commands remain file-only; profiles and their environments are editable in every paired browser.

## Git workflow

These rules apply unless the owner says otherwise for a given task.

- Always work on the `main` branch, in this checkout. Do not create other branches, worktrees or pull requests for this repository.
- When a piece of work is complete, always commit it on `main`. Do not leave finished work uncommitted.
- Before committing, update the documentation so that it matches the new state of the project, and include it in the same commit:
  - `README.md`: status, build and run commands.

The top-bar toggle persists `launchpad-theme` in browser localStorage only (default light); never put it in daemon config or broadcast it to devices. Apply it before paint, synchronize same-browser windows through storage events, key syntax caches by theme and update mounted xterm themes in place. - Click-only UI: keyboard shortcuts are limited to `Ctrl+F` in the code viewer, global `Ctrl+T`/`Cmd+T` for a new terminal, and normal terminal clipboard/clear keys. Every action is a visible button (the find bar also has a Find button). Text fields retain normal editing shortcuts (undo/redo, clipboard, selection and caret/word navigation). The Linux desktop shell supplies Ctrl+Z undo and Ctrl+Shift+Z/Ctrl+Y redo through WebKit’s native editing history, excluding terminal input. Text fields only type text, with three exceptions (the message box also has a visible paperclip button for files and images): in the composer prompt, `@` (projects) and `#` (issues and PRs) at the start of a word open a suggestion list; in the session message box, `Enter` sends, `Shift+Enter` adds a new line, and standard clipboard paste accepts images (also in the composer prompt); in the find field of the code viewer, `Enter` and `Shift+Enter` go to the next and previous match and `Escape` closes the bar. In a focused integrated terminal, `Ctrl+Shift+C`/`Cmd+C` copies, `Ctrl+Shift+V`/`Ctrl+V`/`Cmd+V` pastes with bracketed-paste support, and `Ctrl+L` (also `Cmd+L` on macOS) sends the normal clear/redraw input to the process. Other keys (`Ctrl+C`, `Ctrl+D` and `Ctrl+F` included) reach the process; the code viewer's `Ctrl+F` handler ignores keys from inside a terminal. See `docs/ARCHITECTURE.md`, sections 8.1 (code viewer) and 9.7 (mention rules).
- Linux (Ubuntu) is the primary target; macOS and Windows are supported. Gate OS-specific APIs and keep native release builds and tests in CI.
- Single user: no backward compatibility, no versioning, no data migration framework. The GitHub cache (`cache.db`) can be deleted and rebuilt at any time. Keep schema changes to `state.db` simple.
- Anything Launchpad prepares for GitHub (pre-draft PRs, comments or reviews written by agents) stays local until the owner publishes it with a click.

## Testing

This is a personal project: move fast and break things.

- Keep tests to the minimum. Most code does not need tests. Do not add tests by default.
- Add a test only for a small, specific part that clearly benefits from it, typically a pure function with tricky edge cases (for example the diff parser or the prompt renderer).
- No mock tests. Do not mock HTTP APIs, harness processes, git or the database.
- No tests that need a server, the network, GitHub, a running agent or the daemon.
- The whole test run must take a few seconds at most. Delete or rewrite a test that becomes slow or flaky.
- Check your changes by building and running the app (dev environment) rather than by writing tests.

## Writing style

- Markdown: never hard-wrap lines. Write each paragraph or list item on one line.
- Use technical American English that non-native speakers can read easily.

- Trace backup (`crates/core/src/trace_backup.rs`): adapters own native trace exports through `Harness::native_trace`; preserve native schemas and filenames. Keep Launchpad metadata/events in `launchpad.json` and `launchpad-events-*.jsonl` sidecars. Never synthesize native traces from normalized events. Snapshot hashes must be independent of event cursors so delayed native writes and terminal continuations are captured; unavailable native histories must not starve other sessions. Regression checks: `cargo test -p launchpad-core trace`.
