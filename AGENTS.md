# Launchpad

Launchpad is a personal desktop app for Linux (primary target), macOS and Windows (Tauri) that launches and drives coding agents (Claude Code, Codex, OpenCode) and replaces the parts of the GitHub UI used every day, with a local cache so nothing feels slow. It has one user, on one machine.

Status: Phase 0 done, Phases 1, 2, 2b, 3, 4, 5 and 6 built and awaiting daily-use checks; the scoped Phase 7 harness registry/OpenCode and variants/cost-limits steps and Phase 7a integrated terminals are built; the UX suggestions pass (2026-10-11, `docs/research/ux-suggestions/`) is built and awaiting daily use; other candidates are deferred until they have an owner-approved scope (see `docs/ROADMAP.md`). Keep the build and run commands below and in `README.md` up to date.

## Commands

- CI linting: `cargo +1.93.1 clippy --workspace --all-targets --locked -- -D warnings` and `(cd web && pnpm typecheck)`. Install the pinned toolchain with `rustup toolchain install 1.93.1 --profile minimal --component clippy`.
- GitHub Actions: `.github/workflows/ci.yml` runs Linux lint and native debug tests on main pushes, pull requests and tags. Release builds/tests run only on tag refs (tag pushes or manual dispatch on a tag), on Ubuntu 22.04, macOS 15 and Windows 2025; manual dispatch on main skips binaries. Linux releases use 22.04 so updates run on the primary machine; verify the downloaded CI binary locally before changing that baseline. Release cache keys include the runner image so newer glibc build objects cannot leak into the 22.04 build. Build the UI before the release daemon so it embeds the assets; keep CI commands and toolchain documentation in sync.
- Build the UI: `cd web && pnpm install && pnpm build` (Node 24 from `web/.nvmrc`, pnpm through Corepack).
- Run the dev daemon: `LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- daemon` (port 7318, data in `~/.local/share/launchpad-dev`). Never stop or restart the prod daemon (port 7317) unless the owner asks: it runs the agents, maybe including you.
- Sign a browser in to the dev daemon: `LAUNCHPAD_PROFILE=dev cargo run -p launchpad -- url`. Headless screenshots work with `google-chrome --headless=new --screenshot=out.png --virtual-time-budget=5000 "<url>"`.
- Local PR CLI: `launchpad pr create|update|show|list`; create/update accept `--title` and `--body-file`. Select the daemon with `LAUNCHPAD_PROFILE`; agents receive the exact CLI path and profile in their prompt, with PowerShell invocation syntax on Windows. The repository skill is `skills/launchpad/SKILL.md`, linked into `~/.agents/skills/launchpad` at daemon startup (a managed copy on Windows, marked by `.launchpad-managed`; other real directories are preserved).
- Agent suggestions: `launchpad suggest comment|review --repo <owner/repo> --number <n> --body-file <file> [--event comment|approve|request-changes] [--session-id <id>]`; reviews require `--head <inspected-commit>`. For local PRs use `--predraft <id>` instead of repo/number. `crates/core/src/suggestions.rs`, `crates/server/src/suggestions.rs` and `web/src/features/suggestions/` keep drafts in `state.db`. The CLI never publishes; only explicit card buttons do. Local PR suggestions become local notes. Automated checks must not post real suggestions. Posting claims survive restarts and uncertain outcomes require checking GitHub before replacing a draft.
- Harnesses: `crates/core/src/harness/mod.rs` is the registration list and common contract; each adapter owns native startup/resume, discovery, monitors, environment markers, terminal commands and title hooks. Add a module and registration; keep identity branches out of core/server/React. UI metadata comes from `GET /api/harnesses`, status from `Status.harnesses`. See `docs/HARNESS_ADAPTERS.md`. OpenCode uses the shared ACP client and native config/auth; no monitored subscription quotas, effort selector or in-turn steering. Named local variants and reported-cost limits are built (`docs/harness-variants-plan.md`); Pi and SSH remain deferred.
- Regenerate the TypeScript types after changing a Rust type shared with the UI: `cargo run -p launchpad -- gen-types`.
- Type-check the UI: `(cd web && pnpm typecheck)`.
- Tests: `cargo test` (the few unit tests in `crates/core`; the desktop crate is excluded by default).
- Dev window: `cargo build -p launchpad-desktop && LAUNCHPAD_PROFILE=dev ./target/debug/launchpad-desktop [--open <route>] [--workspace <id or name>] [--new-window]`. Each dev process is its own window; the prod shell opens extra windows in its warm process.
- Install or update the prod app: `packaging/install.sh` (release build, binaries in `~/.local/bin`, systemd user unit, `.desktop` and autostart entries). It restarts the prod daemon, so only run it when the owner asks.
- Launchpad updates are manual through the platform installers. There is no in-app updater, remote version polling, install lock or scheduler update guard. Prebuilt installers must not load Node/nvm or require source build files.
- macOS installation: `bash packaging/install.sh [--prebuilt]` delegates to `install-macos.sh`, installs launchd agents and `~/Applications/Launchpad.app`. Windows: `powershell -ExecutionPolicy Bypass -File packaging/install.ps1 [-Prebuilt]`, with Start menu and login shortcuts. These installers restart production, so only run when asked. Native CI includes debug tests, release builds/tests and CLI smoke checks for Linux x86_64, macOS ARM64/Intel and Windows x86_64.
- Generated Claude worktrees under `.claude/worktrees/` are ignored in the main checkout; their files and Git state belong to the separate worktree.
- App version: `crates/core/build.rs` embeds the Git commit and main checkout path (for source-build skill discovery). The status bar Details ▾ popover shows the running commit from `/api/status` without a GitHub lookup; the bar itself shows it only in the dev profile.
- Icon assets: keep `packaging/icons/source.png` as the unchanged master. Regenerate PNG/WebP/SVG/ICO/ICNS exports with `python3 packaging/generate-icons.py` (requires Pillow). Update installed icons without restarting the app or daemon with `packaging/install-icons.sh`.
- Project remote metadata (`crates/core/src/projects.rs`) is derived from local Git configuration on reads and every 30 seconds; broadcast project changes only when metadata changes. Keep user-edited project fields independent.
- GitHub inbox: authenticate with `gh auth login`; the dev daemon uses the real GitHub account too. Verify replies and unsubscribe controls without posting comments or muting real threads during automated checks. Local unread actions are safe to check.
- UI rule from spike 4 (WebKitGTK): virtualize every long list, memoize row components, use `useFlushSync: false` on virtualizers, prefer fixed row heights.
- Issues and PRs: `crates/core/src/items.rs`, `crates/server/src/items.rs` and `web/src/features/github/`. Detail/list GETs return cached content; POST refreshes it. Label and reviewer pickers use `GET /api/repo-meta/{owner}/{repo}`, which reads `cache.db` only. Merge is the primary button only when GitHub reports MERGEABLE with CLEAN/HAS_HOOKS on a non-draft PR; otherwise it is secondary and shows the blocking reason. `?draft=<suggestion id|1>` opens Conversation at an agent draft, and an agent-draft banner shows on every tab. GitHub mutations require explicit publication buttons. During automated checks, do not post comments/reviews, request reviewers, change labels/state/draft status, or merge real items. Viewed markers and unsent drafts are safe to check.
- Pre-draft PRs: `crates/core/src/predrafts.rs`, `crates/server/src/predrafts.rs`, and `web/src/features/predrafts/`. Records and notes live in `state.db`; worktrees use `.worktrees/<project-id>/<slug>` and `lp/<slug>` branches. Only explicit Publish pushes and creates a GitHub PR. Automated checks may use throwaway local bare remotes and local discard, but must not publish real PRs. Review uses committed heads; publication and cleanup require idle agents and clean worktrees. A started publication freezes further agent turns in that worktree until the owner finishes publication. A pre-draft whose project was removed shows only an explanation and Discard, which archives the record and closes its sessions/terminals but keeps the worktree folder and branch on disk.
- Workspace polish: External history import is removed; existing saved sessions remain available. `crates/core/src/session_git.rs` reads session Git status and selected-file diffs without git mutations. The desktop shell disables Tauri’s native drop handler so image drops reach the HTML controls. One agent panel is shown at a time; the selected session and session pins persist in browser local storage; named saved layouts are not supported; session titles persist in `state.db`.
- GitHub label filters apply locally to the cached 30 most recently updated open items per issue/PR tab. Keep this scope visible, show GitHub label colors with readable text, and refresh old cached lists that lack labels.
- HTML previews in the code viewer are static, sanitized, and sandboxed with no permissions. Keep scripts, navigation and external resources disabled; inline styles and data images/fonts are supported.
- Integrated terminals: `crates/core/src/terminals.rs`, `crates/server/src/terminals.rs` and `web/src/features/terminals/`. The daemon owns `portable-pty` shells and harness TUIs; restarting it ends them, and output stays in memory (1 MB each). Output goes over one WebSocket per viewer (`/api/terminals/{id}/ws`), never the global bus. Shells open only in a registered project, one of its worktrees or a session folder. "Open in terminal" runs the harness TUI there; the session stays In terminal until Re-attach, and TUIs are outside quota protection. Pre-draft publication and cleanup wait until no terminal runs in the worktree; temporary project cleanup and promotion close the folder's terminals; Settings → General has Close all terminals. Successful shell exits remove their tabs; the last removed terminal in a workspace hides the dock. Failed shells and harness TUIs retain their final output. Forward Ctrl+D to the process without a UI shortcut. Automated checks must close the terminals they open and must not type into harness TUIs.
- Editor integration is removed: do not add editor launch buttons, an editor setting or an editor-opening endpoint.
- Code viewer: `crates/core/src/code.rs` (daemon) and `web/src/features/code/` (UI). Every `/api/code/*` request goes through `code::open`, which only accepts a registered project or one of its git worktrees as `root` and resolves `rev` to a commit id; keep that check for new endpoints. Quote Codex TOML project keys when building terminal handoff arguments, including Windows backslashes. Relative file paths in code API responses use forward slashes on every platform; absolute roots keep native path syntax. The `session` search param adds a "← Back to session" link and is not stored as the last position. Syntax colors run in `highlight.worker.ts` (Shiki, JavaScript regex engine); the worker is an ES module (`worker.format = "es"` in `vite.config.ts`).
- Headless screenshots do not wait for Web Workers with `--virtual-time-budget`, so code colors are missing in them; drive Chrome through the DevTools protocol with real waits to check colors.

## Git workflow

These rules apply unless the owner says otherwise for a given task.

- Always work on the `main` branch, in this checkout. Do not create other branches, worktrees or pull requests for this repository.
- When a piece of work is complete, always commit it on `main`. Do not leave finished work uncommitted.
- Before committing, update the documentation so that it matches the new state of the project, and include it in the same commit:
  - `README.md`: status, build and run commands.
  - `AGENTS.md`: new commands, rules or conventions.
  - `docs/ARCHITECTURE.md`: design changes, and the decisions log when a decision is made or changed.
  - `docs/ROADMAP.md`: the Status column and the items done in the current phase.
  - `docs/design/sketches.html`: when the UI direction changes.
- Use a short commit message that says what changed.

## Product rules

- Phase 7 extensions require a concrete owner-approved scope and acceptance check. The harness registry/OpenCode first step and integrated terminals (`docs/integrated-terminal-plan.md`) are selected and built; other candidates remain deferred. Session workers and remote browser mode were reverted; the daemon owns harnesses and terminals, and restarting it interrupts active turns.

- Project pages show stat chips (running · waiting · pre-draft, using `needsYou` for waiting), Running agents, GitHub items, Worktrees, then All agents (including running sessions). Use the shared Running predicate and virtualize both agent lists. Empty agent sections are one muted line; empty GitHub tabs shrink to their message. Item rows (52 px) link in-app with no per-row GitHub/+Add buttons; a sticky selection bar offers Launch with these, Add to draft and Clear. Worktree rows show branch, newest session status, pre-draft link/state and Agent/Launch here (pre-draft worktrees only)/Code/Terminal.
- Quota protection (`crates/core/src/quota.rs`): Allow paid usage defaults to false and is never remembered as a launch default. Known included-quota exhaustion holds new input or interrupts protected sessions into Quota paused, between Running and Done. Automatic continuation requires fresh confirmed capacity in both windows and finished outstanding commands; never infer availability from reset time alone. Stop on a quota pause cancels continuation into Done; ordinary Stop stays Stopped. Pauses and pending input are durable, uncertain continuation claims are never retried automatically, and manual Resume with paid usage opts that session into additional spending. Manual Retry with subscription only keeps paid usage off and ignores an old quota snapshot for that session until a new reading arrives; it may still incur paid credits if included quota is exhausted. Sessions with paid usage on show a Paid usage on badge in the header with a Use subscription only button; Summary → Run can switch either way (`POST /api/sessions/{id}/paid-usage`). Unknown readings permit manual work with a notice. Terminal handoffs are outside protection. Protect auxiliary title requests too; persist pending naming across quota pauses and retry for attached, unpaused sessions with capacity. Manual title edits cancel pending naming, and concurrent title requests for one session are deduplicated. Never refresh Claude OAuth. Scheduled follow-ups wait behind pauses; crons requiring a finished previous run also wait for quota-paused runs. Publication idle checks must include commands that outlive interruption.
- Subagents: `EventBody::Subagent` metadata and `SubagentEvent` envelopes share the root session's durable sequence; child deltas remain ephemeral and are scoped by agent ID. Native ancestry and protocol parsing belong to the adapters. `Sink::child` must never change root usage/model/identity/status or last-message previews. Keep child traces read-only and virtualized; route native questions to the parent session's answer controls. Include child turns/tools in idle checks and root Stop/quota interruption. Older ACP delegation-only records are superseded when native child events become available. See `docs/subagents-plan.md`.
- Agent groups: Done means waiting for input; Running includes starting, working and background commands. Never infer Done from a command being silent. Needs you = an open question, or Done/Failed/Interrupted and unseen; unseen means `session.seen_at < status_since` (no separate unread flag). `Session::needs_you()` (Rust) and `needsYou`/`isUnseen` (`web/src/lib/sessionStatus.ts`) are the shared predicate. A session becomes seen (`POST /api/sessions/{id}/seen`, `useSeen.ts`) after a focused, visible window has shown it for 1.5 s. `SessionCounts.done` counts needs-you sessions. Sidebar counts (words: N waiting, N running, N paused), project markers and project stat chips must use the same predicates.
- Agent list rows offer a compact icon on hover or focus: Stop for Running and Quota paused, Archive for other unarchived sessions. The action does not select the row or open its panel; archived rows have no quick action. Touch devices keep the icon visible.
- Agent list group order: Needs you (questions, unseen Done newest first, unseen Failed/Interrupted), Running, Quota paused, Done (seen, newest first), Stopped, Interrupted, Failed, In terminal, Cron, Scheduled, Archived. Groups collapse independently using their headings; Cron and Scheduled start collapsed and show the next run time in their heading. Groups with no items are hidden. Archived contains only explicitly archived (`closed`) sessions; never use it as a catch-all. Keep counts visible, remember collapse state in the persisted UI layout, and omit hidden rows from the virtualizer. Rows show project + last message (`session.last_message`) on the second line, a badge only for Question, Failed, Interrupted and Quota paused (one shared pill shape), otherwise the age or a spinner. Done ends with Archive N seen, older than 3 d (pinned sessions are kept). With nothing selected, Agents shows a dashboard without automatically opening or marking any run seen; archiving the shown session opens the next item of its group. Temporary folders in the sidebar list only those with agents that need you, run or are quota paused, plus a + N more toggle, with the `tmp-MMDD-` prefix hidden.
- Model and effort are editable on a launched session in Summary → Run (`POST /api/sessions/{id}/model`). Codex applies them from the next turn; Claude restarts its idle process with `--resume` (after the running turn otherwise). The change never touches the launch spec or launch defaults.
- Resume with another agent prepares a fresh composer draft for any non-running session outside a terminal. Freeze its trace at `last_seq` and use `Target::SessionFolder` to retain its folder; resolve pre-draft folders through ExistingPredraft and its publication/idle checks. Require an explicit Replace draft click when a draft exists. Keep the source state and paid-usage setting unchanged; the new draft starts with paid usage off.
- Session titles are editable in place by clicking the title, with visible Save title and Cancel buttons. A ★ before the title marks pinned sessions. The header has Summary · Trace · Changes tabs (Changes is the read-only Git view, hidden outside a Git repository), one state-dependent primary button (Running/Quota paused → Stop; Question → Answer; Done → Review changes if files changed, else Archive; Stopped/Failed/Interrupted → Resume; In terminal → Re-attach), a fixed Terminal button, and More ▾ (Open in terminal, Files, Use trace as context, Archive when not primary, Pin/Unpin). Warning badges stay in the header.
- Initial final messages: the shared launch preview appends `compose::append_initial_summary_instruction` after other launch context for every harness, including scheduled and cron launches. Ask for a concise, complete outcome/results/checks/remaining-work summary only for the initial task; user steering and specific response requests take precedence. Keep follow-up messages verbatim and empty prompts empty.
- Session summaries (S8): each panel load of a non-running session opens Summary; Running always shows Trace, and a turn ending in Trace keeps it with a state bar. One white column shows recorded run facts, the first prompt, the exact last markdown message and fact-based Next steps; hide missing values and never parse free text for actions. Next steps add one Review & post step per unposted suggestion of the session and Review & publish for its pre-draft; Schedule follow-up is a small link after them. The first user message shows the typed text; blocks appended by `compose.rs` fold under + Launchpad instructions (N), so keep the typed text first in `render_prompt`. Consecutive system notices fold into one expandable trace line. Stopped is distinct from Interrupted and Failed and never counts as Done. Summary Resume sends “Continue the unfinished turn.” for unfinished turns; archived Resume re-attaches without sending. Follow-ups extend scheduled launches with `resume_session_id` and send the saved message verbatim to that same session. They use the existing AND conditions, fresh reported quota deadlines, claim-before-send; claims are never automatically retried after a crash. A queued follow-up waits while its target runs, is in a terminal or has an unanswered question. Cancel test follow-ups and keep all GitHub publication behind owner buttons.
- The session header X only closes the panel, returns to the Agents dashboard and never changes session state or opens another run. Archive is a separate action (primary button or More ▾); archived sessions remain resumable and appear in Archived.
- Delayed launches stay in the separate Scheduled group, never in Running or Done. Agent dependencies can select existing sessions or scheduled launches; scheduled ids become session ids at launch. Dependencies use the same Done predicate as the rest of the UI, and cancelled or missing launches never count as Done. Quota delays save a fresh reported reset timestamp at scheduling time; never guess a reset or refresh Claude OAuth. Claimed launches are not automatically retried after a crash. Scheduled is independently collapsible like the other agent groups. A launch can combine several start conditions; all must be met (AND, no OR).
- Cron agents (`crates/core/src/crons.rs`, `web/src/features/agents/CronPane.tsx`, `web/src/features/launch/CronSelector.tsx`) stay in their own Cron group; each run is a normal session. Schedules are 5-field cron in local time. The scheduler claims a run by advancing `next_run_at` before launching and never catches up: failed conditions and runs more than 1 hour late are skipped. Quota conditions need a fresh reading (15 minutes) and never guess. Automated checks must pause or delete test crons.
- Workspaces (`crates/core/src/workspace.rs`, `web/src/lib/workspace.ts`, `web/src/stores/workspace.ts`, `web/src/features/workspaces/`) are named sets of projects. Sessions, scheduled launches, crons and inbox threads belong to a workspace only through their project or repository (or the `workspace_id` of the launch spec); do not add another ownership field. Every narrowed list uses the `useScope()` predicates so counts agree. The workspace is chosen per window (`sessionStorage`) and switches in place using visible buttons in the single-row top bar, beside the Launchpad brand on the left, with Launch at the right; the header wraps only when the window is too narrow, so every workspace stays accessible, and one Open in new window ▾ menu opens any workspace in another window. Settings → Workspaces (`/settings/workspaces`) creates, renames and deletes workspaces. All workspaces shows every project; its Pinned sidebar combines non-temporary projects from every workspace with explicitly pinned projects, without duplicates. The Inbox keeps a visible All repos button next to its searchable Repository ▾ popover. Session selection and composer drafts are per workspace. `session_git.rs` is the read-only session Git panel, not a workspace.
- Agent trace context: `LaunchSpec.agent_traces` stores session ids and fixed `through_seq` boundaries. Preview and launch only reference each trace with the exact `launchpad trace <session-id> --through <seq>` command (`GET /api/sessions/{id}/trace`); never inline the trace in the prompt. The command renders the stored events, including archived/imported sessions, with messages, reasoning and tool activity; list image names without embedding image bytes, and never include live partial output. Missing traces fail visibly rather than silently dropping context. The composer picker is searchable and virtualized.
- Harness variants: `[[variants]]` in config.toml and Settings → Harnesses configure stable IDs, display names, environment overrides, model/effort defaults and billing. Sessions store the ID, never environment values; missing IDs or changed base harnesses fail visibly on resume. Subscription variants use the base account quota monitor; PAYG bypasses it. Claude/OpenCode cost limits (`POST /api/sessions/{id}/budget`) block input at reported cumulative USD cost and interrupt active turns best effort. Codex has no USD cost capability. PAYG and cost-limited sessions use prompt titles; terminal TUIs remain outside protection. Saved config files use mode 0600 on Unix.
- Model discovery: GET `/api/harness/{kind}/defaults` returns cached models; POST queries that harness again and preserves the last successful list on failure. The launch panel’s refresh icon (with a tooltip and accessible label) and Refresh models menu item share this operation and never change the selected model.
- New drafts select the latest successfully launched harness/variant. Model and effort defaults come from the latest successfully launched spec for each harness/variant across all projects and workspaces, restored from saved sessions. Harness clicks and unsent edits do not change remembered defaults; opening or adding context to an existing draft preserves its choices.
- Composer project picker: opening the dropdown focuses its fuzzy search field (names, repositories, descriptions and paths); keep workspace grouping, virtualized fixed-height rows and the temporary-folder action.
- Composer attachments: `LaunchSpec.attachments` stores uploaded data URLs in drafts, schedules and crons. Pick or drop files/images, or paste screenshots into the prompt; eight files, 5 MB each, 20 MB total. Images go through native harness input, including quota-held launches. Other uploads are private local copies in `<data_dir>/attachments/<session-id>/`, referenced in the prompt and allowed on resume; never write them into the project checkout. Both message boxes share clipboard extraction and file reading in `web/src/lib/attachments.ts`.
- Composer: `open` means a draft exists; Minimize (persisted with the draft) turns it into a draft pill next to Launch in the top bar, which flashes when + Add buttons add context. + Add buttons show whenever a draft exists; adding context keeps a minimized draft minimized, Launch buttons open it. Below 1,250 CSS px (1,500 px at 120%) the drawer is an overlay. Order: prompt first, Project · Run in, context chips + one + Add context popover, one option summary line (warning color for paid usage, PAYG, cost limit, delayed start, cron, missing variant) that toggles the options panel, Preview prompt popover (fetched only while open; Launch never waits for it), then Open after launch, Discard, Launch.
- To publish (`/publish`, `web/src/features/publish/`, sidebar count from `usePublishItems()`) lists unposted agent suggestions and unpublished, unarchived pre-drafts with `useScope()`, newest first and virtualized. It only links to the review pages (and Discard with confirmation for suggestions); nothing is posted from it.
- Inbox triage: reason chips with counts (Review requested, Mentioned incl. team mentions, Assigned, Subscribed = every other reason, All, default All), plus Unread only and repository filters. Each row has visible ✓ Done, ▶ Launch and + Add (when a draft exists); Read/Unread and Unsubscribe are in the preview pane. After Done/Unsubscribe the next row is selected; opening the Inbox selects the first unread review request (else first unread) without marking it read. The sidebar count is unread review requests + mentions + assignments (`useInboxNeeds()`). Previews render GitHub `body_html` with the sanitized renderer (Markdown fallback); images are not proxied there.
- Status bar: one row with a compact meter pair per harness with quotas, warning tokens only when needed (updating, not found, quota reading older than 15 min, GitHub < 500 calls left), the Terminal button, connection warnings and a Details ▾ popover (versions, resets, errors, GitHub rate limits, commit, profile). Agent counts live in the sidebar only. Breadcrumbs: `<project or repo> / Pull requests|Issues / #N` and `<project> / Pre-draft PRs / <title>`; none on Inbox and Agents. Settings pages use one sticky Unsaved changes · Revert · Save bar.
- General zoom has five positions (100%, 110%, 120%, 135%, 150%), with 120% as the default. Scale the entire interface and keep list virtualization working at every position.
- Light theme only. Do not add a dark theme or dark-mode styles.
- Click-only UI: no keyboard shortcuts, except `Ctrl+F`, which opens the find bar in the code viewer. Every action is a visible button (the find bar also has a Find button). Text fields only type text, with three exceptions (the message box also has a visible paperclip button for images): in the composer prompt, `@` (projects) and `#` (issues and PRs) at the start of a word open a suggestion list; in the session message box, `Enter` sends, `Shift+Enter` adds a new line, and standard clipboard paste accepts images (also in the composer prompt); in the find field of the code viewer, `Enter` and `Shift+Enter` go to the next and previous match and `Escape` closes the bar. A focused integrated terminal receives every key (`Ctrl+C` and `Ctrl+F` included) and Launchpad defines no shortcut there; the code viewer's `Ctrl+F` handler ignores keys from inside a terminal. See `docs/ARCHITECTURE.md`, sections 8.1 (code viewer) and 9.7 (mention rules).
- Linux (Ubuntu) is the primary target; macOS and Windows are supported. Gate OS-specific APIs and keep native release builds and tests in CI.
- Single user: no backward compatibility, no versioning, no data migration framework. The GitHub cache (`cache.db`) can be deleted and rebuilt at any time. Keep schema changes to `state.db` simple.
- Anything Launchpad prepares for GitHub (pre-draft PRs, comments or reviews written by agents) stays local until the owner publishes it with a click.
- GitHub notifications: `all=true` returns historical Done threads too and has no Done/inbox field. Never treat the REST history as the web inbox or promise exact parity. Keep membership in `state.db`; a missing thread subscription (404) is not evidence of unsubscribe.
- Never refresh the Claude OAuth token. Read it only (see `docs/ARCHITECTURE.md`, section 9.5).

## Testing

This is a personal project: move fast and break things.

- Keep tests to the minimum. Most code does not need tests. Do not add tests by default.
- Add a test only for a small, specific part that clearly benefits from it, typically a pure function with tricky edge cases (for example the diff parser or the prompt renderer).
- No mock tests. Do not mock HTTP APIs, harness processes, git or the database.
- No tests that need a server, the network, GitHub, a running agent or the daemon.
- The whole test run must take a few seconds at most. Delete or rewrite a test that becomes slow or flaky.
- Check your changes by building and running the app (dev profile) rather than by writing tests.

## Writing style

- Markdown: never hard-wrap lines. Write each paragraph or list item on one line.
- Use technical American English that non-native speakers can read easily.
