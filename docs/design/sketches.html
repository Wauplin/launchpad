Launchpad sketches

Eight static mockups of the main screens, filled with example data. Use the theme toggle below to compare light and dark palettes. In the app, the Light / Dark button beside Launch saves the choice on this device only. The UI is click only, with one keyboard shortcut: Ctrl+F opens find in the code viewer. Typing helpers include @ and # suggestions in the composer prompt and screenshot paste in both the composer prompt and session message box. Pink numbered pins in each window match the notes below it. The design rationale is in docs/ARCHITECTURE.md.

Update · UX suggestions pass (2026-10-11)

Direction changes since these sketches were drawn

The owner approved the 12 suggestions of docs/research/ux-suggestions/index.html, which has the interactive sketches of the new direction. Where a mockup below disagrees with this list, this list wins. The mockups were not redrawn.

  1. Terminal shortcuts (2026-10-12). The dock keeps New terminal, tabs, height and Hide; Copy selection, Paste and Clear buttons are removed. Ctrl+Shift+C copies and Ctrl+Shift+V or Ctrl+V pastes (Cmd+C/V on macOS). Ctrl+L clears/redraws through the shell; Cmd+L is the macOS alias. Ctrl+C still interrupts. Ctrl+T/Cmd+T opens a new terminal anywhere in the desktop app, even with the dock hidden, using the folder on screen, active workspace terminal folder or first workspace project.
  2. Needs you (S3). A first agent group collects questions and Done, Failed or Interrupted sessions you have not seen yet (seen after 1.5 s on screen). Group order: Needs you, Running, Quota paused, Done (seen), Stopped, Interrupted, Failed, In terminal, Cron, Scheduled (both collapsed by default), Archived. Rows show project and last message; badges only for Question, Failed, Interrupted and Quota paused. Seen Done, Failed and Interrupted rows offer a mail icon to Mark unread for later and return to Needs you; marking the selected run unread closes its panel. Done ends with Archive seen, older than 3 d. With nothing selected or after closing a session panel or archiving its run, Agents shows the dashboard without opening or marking another run seen. The dashboard stays in a centered 560 px maximum-width column inside the right panel; long rows truncate and quota details wrap. The dashboard shows Quota paused after Running, with a count, up to eight newest clickable sessions, a muted empty state and an overflow notice. It shows queued scheduled launches, including jobs without known trigger times, with a short condition line and the next active cron. The sidebar shows counts as words (N waiting, N running, N paused), wrapping beneath Agents in a row that grows to fit; it lists only active temporary folders.
  3. Session header (S3, S8). Summary · Trace · Changes tabs (Changes replaces the Git toggle), one primary button that depends on the state (Stop, Answer, Review changes, Archive, Resume, Re-attach). Done uses Archive for a clean session folder and Review changes for uncommitted files; committed differences remain in Changes. Terminal and More ▾ (Open in terminal, Files, Use trace as context, Archive, Pin). A ★ before the title marks pins. The model · effort chip is only in Summary → Run. The message box has a paperclip button. The trace folds Launchpad instructions and repeated system notices.
  4. Composer (S2). Prompt first, Project · Run in on one line, context chips with one + Add context popover, one summary line of options (warning color for paid usage, PAYG, cost limits, delayed starts, crons), Preview prompt as a popover. Minimize turns the draft into a pill next to Launch in the top bar; narrow windows show the drawer as an overlay.
  5. Inbox (S1). Reason chips (Review requested, Mentioned, Assigned, Subscribed, All), Unread only and a searchable Repository ▾ popover. Every row shows Done, Launch and + Add buttons, not hover actions; Read/Unread and Unsubscribe are in the preview pane, which renders GitHub HTML. The sidebar count is unread review requests, mentions and assignments.
  6. To publish. A sidebar page under Agents lists unposted agent suggestions and unpublished pre-drafts with Review links. Nothing is posted from it.
  7. PR and project pages (S4, S5). An agent-draft banner on every PR tab; Merge is primary only when GitHub reports the PR as cleanly mergeable; searchable label and reviewer pickers; breadcrumbs. Project pages have stat chips, compact item rows and a sticky selection bar.
  8. Chrome (S1, S6). One Open in new window ▾ menu replaces the per-workspace window buttons. The status bar is one row of compact quota meters and warnings, with a popover opened by clicking either harness’s quota meters (versions, resets, errors, GitHub rate limits, commit); agent counts live in the sidebar only. Settings use one sticky Unsaved changes · Revert · Save bar.
S1 · Inbox

Notifications triaged from the local cache

The default screen. List and preview sit side by side, so going from one thread to the next never loads a page. Everything here renders from SQLite and refreshes in the background. Visible buttons on the left of the top bar, beside Launchpad, pick this window's workspace (a named set of projects) in one click or open another window on a different one; Settings → Workspaces edits them; All workspaces combines every workspace’s sidebar folders and explicit project pins without duplicates; the sidebar, agents and inbox then only show that workspace, and the inbox has an All repos button to see every notification.

  2. 2Summary or Trace. A toggle in the session header. Each time the panel loads a session that is not running (click in the list, startup, workspace switch), it opens on Summary. The header keeps the Changes tab, the state-dependent primary button, Follow-up agent for idle sessions, Terminal, More ▾ and the X, so the summary has no separate action bar. The X closes the panel and returns to the Agents dashboard without opening another run.
  3. 3Run metadata. Recorded turn duration and count (idle time excluded), cost and tokens (cost for Claude only), model and context, folder, branch and push state, changed files compared to main, context items, and the exit code of the last command.   4. 4Final message. The last agent message, rendered as markdown at full width, with Copy and Copy as text. Very long messages fold after about 30 lines with "Show full message". Decided on 9 October

  1. A summary view, not an overlay. The summary replaces the trace in the panel. No transparency or blur.
  2. Opens on every load. Every time the panel loads a session that is not running, it shows Summary first.
  3. Simple next steps. Only Launchpad facts and the options of an agent question. No change to the Launchpad skill and no parsing of a "Next steps" list.
  4. Follow-up, not relaunch. Continue in the same session with Schedule follow-up or the message box. No Relaunch button to start a new session with the same spec.
  5. One plain column, no action bar. Run metadata, task, final message and next steps follow each other on one white surface, separated by thin lines, without cards or gray gaps. Archive and Summary/Trace live in the header; other state-specific actions are Next steps rows.
  6. One panel size. The agents page shows one session at a time, so there is no compact version for small panes.
