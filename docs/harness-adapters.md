# Harness adapters

The registration list in `crates/core/src/harness/mod.rs` is the only host list of harness identities. Claude Code, Codex and OpenCode are registered integrations. Pi is intentionally left for a follow-up that checks this boundary in practice.

## Files to change

1. Add `crates/core/src/harness/<name>.rs`, with private protocol helpers and an SVG asset if needed.
2. Declare the module and add its `REGISTRATION` to `REGISTRATIONS` in `harness/mod.rs`.
3. Run `cargo run -p launchpad -- gen-types` when changing shared metadata types. Registering an adapter alone does not change the shared types.

A registration contains an ID (`HarnessKind::new("stable-id")`), display metadata, integration capabilities, documented environment variables (`env_vars`), the variables that select another subscription login (`account_env`, for example `CLAUDE_CONFIG_DIR`) and preset profiles (`profile_templates`, each with a `ProfileKind`: subscription, API key or provider) for Settings → Profiles, an adapter factory and an inherited-environment-marker predicate. The ID is stored in sessions, launch specs and schedules. IDs must be unique; unknown IDs fail explicitly. Native conversation IDs remain opaque strings. Assets live beside the module, with their source/license recorded in `harness/icons/README.md`.

`Harness` is the adapter contract. Only startup and version discovery are required; defaults for optional hooks return empty discovery, no services/title request, or a clear unsupported error. Set capabilities only for hooks actually implemented. For cost-reporting adapters, `cost_model_prefixes` restricts pricing to supported model families (empty means unrestricted). Never forward fallback prices for unknown models: set `Usage.cost_unavailable` and clear `cost_usd`; the host retains tokens, disables cost management and warns the owner. The factory can own a shared native process and routing state, as Codex does; it can also be stateless and create one process per session.

## Native behavior belongs in the adapter

- `start`: create or resume the native conversation from `StartSpec`, set its ID/model through `Sink`, and return a `LiveSession`.
- `LiveSession`: implement input and delivery acknowledgments, interruption, structured answers and final process stop. `turn_active` covers a turn waiting for input too. `ready_for_turn` must remain false until outstanding commands and questions settle. A silent command is still running. Expose `has_open_questions` if multiple requests can be pending. Optional `set_model` applies model/effort overrides from the next turn; return false to have the host replace the idle process with a native resume on the next input. Tool-call events upsert metadata by item ID when native inputs/titles arrive later. Emit final messages and `TurnEnd` before the final status; preserve Stopped/Interrupted on cancellation.
- `skill_locations` / `skill_instruction`: declare ordered project/global/config roots for prompt completion and render explicit invocation. Profile and host configuration is resolved by the shared read-only discovery service; keep vendor directory names and invocation behavior in the adapter. The current fallback reads selected `SKILL.md` files explicitly; native slash dispatch requires transport-specific validation.
- `models`, `defaults`, `efforts`, `version`: read native discovery/configuration. The host polls model lists independently so one missing executable does not block other integrations. Version errors appear beside the harness in the status bar.
- `spawn_services`: start notification routing or updates. Publish version data through `StatusHandle::update_harness(ID, ...)`.
- `spawn_quota`: poll the included quota of one subscription login (`quota::QuotaAccount`: its key and its `account_env` values expanded on this computer) and publish it with `StatusHandle::update_quota(&account.key, ...)` or `quota_error`. The host calls it once per login used by a subscription profile and aborts the returned task when no profile uses it; do not put provider parsing or daemon-owned native process fields in `App`.
- `terminal_command`/`terminal_env`/`terminal_resume_markers`: return an argument vector, native environment overrides and markers identifying the native resume command. The host resolves the executable and opens the integrated terminal on Linux/macOS/Windows.
- `project_moved`: relocate native path-dependent history when a temporary project is promoted, if necessary.
- `title_command`/`title_response`: optional auxiliary title request. The host handles timeout and subscription protection, then adds the cost the reply reports to the session usage. Codex parses its event stream and reports no cost; Claude reads `--output-format json` and returns `total_cost_usd`. With no hook, the local prompt-based title stays.
- `environment_marker`: remove only inherited session markers that should not reach another process. Credentials and normal native configuration stay in the user's environment.

The host owns persistence, prompts, project/worktree creation, scheduling, quota holds and publication guards. Normalize protocol output into the existing event model rather than exposing protocol-specific fields to React. A genuinely new interaction may require extending the shared contract; adding a harness with existing interactions should not.

## Reusing ACP

OpenCode is the first consumer of `harness::acp::start(command, spec, sink, extensions)`. Its module supplies native child-update capabilities/translation and delegation-tool identification through `Extensions`, as well as `opencode acp` with the correct working directory/environment, CLI model/version discovery, metadata and terminal resume arguments. The reusable client handles stdio JSON-RPC v1, negotiated new/load/resume, model config options, text/images, ordered updates, tool completion, permission cards, cancellation and transport failure. It advertises no client filesystem or terminal services: the harness runs its own tools.

ACP permission responses select an advertised option; arbitrary typed answers are rejected. Image support is checked against the negotiated agent capability as well as the static integration descriptor; a selected model may still reject an unsupported image. ACP tool output snapshots are converted to incremental output, and reported before/after texts become unified diff previews. Native agents may report only the replaced fragment; the Git panel remains the source for full-file diffs. Reported USD usage is cumulative, without claiming that the provider billed that amount.

Current OpenCode limits are explicit: no messages while a turn is running, effort override, auxiliary AI title, subscription quota monitor or hard spending cap. Native configuration, credentials, model defaults and permissions remain OpenCode's responsibility. Profiles pass environment overrides through `StartSpec.env`; adapters must apply them to every native session process. The host resolves profile defaults and billing, and `capabilities.cost` enables limits based on cumulative reported USD usage. Claude and OpenCode support this; Codex does not report dollars. SSH and billing ledgers remain deferred.

## Checks

Run strict workspace Clippy, UI typecheck/build and the existing short pure-function tests. Exercise the installed native process through an isolated dev database: launch, stream, follow-up, permission answer, stop, archive and resume. Inspect the composer and session controls for capability handling. Do not mock harnesses, publish GitHub items, restart production or start uncancelled test schedules/crons. Keep native behavior gated appropriately for supported operating systems.

## Native subagents

Emit `Subagent` metadata with the reported native ID and direct parent, then normalize each child's events through `sink.child(id)`. Child sinks preserve the root session ID and sequence while wrapping events; they must not update root usage, model, identity or preview text. Root-facing native questions still use the root answer routing. Include observed child turns/tools in `ready_for_turn` and interruption; never infer completion from silence. Persist only reported states and show unavailable traces honestly. The UI consumes the shared envelopes without harness identity branches. OpenCode's optional ACP child extension stays in its adapter; older versions can expose delegation-only records, which native records supersede.

## Permission modes

Claude and Codex advertise `capabilities.permission_modes`. The composer offers **YOLO** (initial default), **Ask for approval**, and **Auto approval**. The launch spec stores `permission_mode`, including for scheduled launches; old specs deserialize to YOLO. Successful launches restore defaults independently for each harness/profile, like model and effort. A deliberate mode selection is also remembered immediately on that browser, before launch. Restored unsent drafts retain their own mode.

Claude uses `--permission-mode auto` for its native AI classifier or `--permission-mode default` for manual approvals, with `can_use_tool` requests sent to explicit approval cards. Codex uses `approvalPolicy: untrusted` and `sandbox: workspace-write`; safe reads and operations allowed by native rules may proceed without prompting. Codex Auto uses `approvalPolicy: on-request`, `approvalsReviewer: auto_review` and `sandbox: workspace-write`; manual approval explicitly selects `approvalsReviewer: user`, independently of native configuration. Auto startup/resume checks the returned reviewer and fails visibly if it was not enabled. Native account, model and managed policy restrictions still apply; Claude reports a visible notice if initialization selects a different mode. YOLO keeps the previous bypass flags/policies. Resume and terminal handoff carry the saved mode. OpenCode continues to use its native permissions.

Approval cards show the requested tool input, command, working folder, reason or proposed file changes where supplied. They appear in Trace, Summary and phone Now, with explicit choices and touch-sized buttons. Codex offers session approval when the native protocol permits it. Typed replies cannot grant permission; invalid or stale choices are rejected. Cancellation, archive and process exits settle requests, and child requests route through their parent session. Explicit Cancel turn decisions use `LiveSession::answer_stops_turn` so the host treats them as silent owner stops. Approval waits are silent under the existing notification policy.

Codex native `item/autoApprovalReview/started|completed` events become distinct **AI approval review** tool cards, with the reported action, decision, risk and rationale; native reviewer warnings become notices. They do not ask the owner to approve the AI review itself or create normal coding-agent records. Human-only native requests continue to use permission cards. Auto is native AI review, not Codex's `--full-auto` preset or Launchpad automatically accepting permission requests. See [Codex Auto-review](https://developers.openai.com/codex/concepts/sandboxing/auto-review) and [Claude permission modes](https://code.claude.com/docs/en/permission-modes).

Permission modes are editable in the session header on desktop and phone, as well as the Summary. `POST /api/sessions/{id}/permissions` persists the choice for this conversation and native resume/terminal handoff. A running turn is interrupted as an owner action, then resumed with the same native conversation ID and a continuation message after its outstanding commands settle. Pending requests are cancelled rather than granted; the agent reconsiders the action under the new native mode. Idle/archived sessions use the new setting on their next turn. This reuses native startup/resume enforcement rather than assuming a settings update changes an already-running turn. Quota, cost, publication, setup and terminal guards still apply; background commands must finish before replacement. If interruption does not settle within 20 seconds, the mode is unchanged and the owner can retry once idle. OpenCode keeps native configuration.
