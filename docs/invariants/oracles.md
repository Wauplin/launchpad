# Oracles

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- An oracle is one Python file `oracles/<slug>.py` in the workspace's store `oracles-<workspace id>`, written only by Home through `launchpad_automation::oracles` (`plain::write_texts` with its author; `plain::commit` refuses it), so it has Versions, diff and Restore; the `oracle` table keeps its authors and `paused`. It starts with a `# /// oracle` block (TOML: `title`, `description`, `tools` among http, github, huggingface and launchpad, `min_interval` ≥ 1m, `timeout` ≤ 60 s; unknown keys refused). Its parameters are the arguments of `def check(...)` (`oracle_check::signature`: each annotated `str`, `int`, `float` or `bool`, optionally `| None`, literal defaults, no `*args`/`**kwargs`; `cursor: str | None` and `now: datetime` are Home's to give). No dependencies: Monty's standard library and `launchpad_oracle` (embedded, `crates/automation/oracle/`, with its `.pyi`) only.
- Pre-check (`oracle_check::precheck`) on every save, draft run and oracle card filing: header, `ruff check --fix` (fixed rule set E9,F,I, `--isolated`, F841 made a safe fix) and `ruff format` (line length 112) on stdin, the signature, Monty's parser (in process, nesting-bounded, on a big-stack thread), then the type checker in a worker (warnings only). Refused files (`oracle_check::Refused`, HTTP 422 with `problems`, CLI exit 3) are neither saved nor run; what passes is stored and run formatted. A stored file that no longer passes (an older format, a Restore) stays stored and is broken (`Oracle.problems`, decided from the file and cached by hash, never a flag): never evaluated (callers get an error), a gate's tick on it is a quiet check `oracle broken: <reason>`, and Today shows its row until it is saved again.
- Evaluations run only on Home (`oracle_eval::run`, one path for drafts and saved oracles) in Monty through monty-pool (`oracle_monty`: the `monty` worker binary, a fresh process per evaluation, empty environment, 128 MiB, frozen UTC clock at `now`, `random` seeded by the evaluation, no sleep, 16 at once), each in its own task. Tools reach the outside only through the host functions `launchpad_host.call`/`fail`, checked, run and logged by `oracle_tools` (200 calls, 10 MiB per body, 50 MiB per evaluation): every HTTP call is a GET of one shared client whose resolver refuses non-public addresses except registry hosts (connections go only to checked addresses, redirects checked per hop, a credential only for its tool's own host); github and huggingface use the registry tools gh and hf (`vault::oracle_registry_tool`, `vault::oracle_token`, read in Home's process only); launchpad commands are in-process GETs of Home's router as a read-level principal of the workspace (`launchpad_server::oracle_read` through `ext::Extensions::oracle_read`, the request extension `launchpad_http::OracleReader` checked by `agent_auth::authorize_oracle`; never `oracle.run`/`test`, no token). Secrets never enter the worker; results are redacted again (`oracle_eval::redact`). Outcomes are True, False or Failed with a class (access, http, timeout, limit, script, contract, declared), never folded into False; tools raise built-in exceptions (`PermissionError`, `ValueError`, `OSError`, `RuntimeError`), and one Home raised keeps its class when uncaught; the deadline (also during a tool call) and the budgets end the evaluation at once, never as an exception. A saved oracle shares one flight per (workspace, file hash, params, input cursor) and reuses an answer within `min_interval`; drafts share nothing and record nothing. Evaluations (with their log and call log) are kept 30 days with their callers and consequences; cursors belong to consumers (`oracle_cursor`: `routine:<id>`, `cli:<workspace>:<oracle>:<name>`) and commit only when the consumer acts; `oracle_streak` keeps each oracle's failure streak.
- Gates (`gates.rs`): a routine's optional `[gate]` (bot routine files and routine records), schedule triggers only: an `oracle` of the routine's workspace, `params`, `run_on`, `fire` (required, no default: `change` or `every`), optional `cooldown`, `remind` and `[gate.failed] instructions`. Each due tick evaluates first; a routed outcome the fire policy lets through starts the run as usual (quota, loop guard, thread cap and limits unchanged) with the evidence fenced in its message; anything else is a quiet check (`RunOutcome::Checked`: no thread, session or quota; consecutive ones collapse, and `crons::trim_history` drops checks before runs), also for a paused or broken oracle. A routed Failed fires once per failure streak, and one evaluation starts one run at most. The cursor and the fire state commit in the run's claim (`crons::start`); a held-back run commits nothing, a False that starts nothing commits at once, and a gate changed while it evaluated keeps neither (`gates::same_gate`). Run now ignores the gate.
- Today: one Fix row per failing oracle (`oracle:<workspace>/<slug>`, from its open streak, with the failing call and the routines gated on it), updated in place; Done at the next True or False (“Recovered after N”) or at Mark read until the next failure; a broken oracle has the same row ("is broken", with why) until it is saved again; hidden while the oracle is paused. A gate's oracle failure is a quiet check, never a “Routine failed” row.
- Access (`/api/oracles/{workspace}…`, Home-owned, `crates/api/src/oracles.rs`, `Names::Workspace`): every Launchpad CLI level reads (list, show, evaluations, versions, `_tools`, `_interface`) and runs (`oracle.run`); propose tests drafts (`oracle.test` with `content` only, `agent_auth::oracle_test`); `oracle.save` (admin), `oracle.pause` and `oracle.resume` are admin; an agent's save, draft or card accept may use github and huggingface only when its own session holds that registry tool (`vault::session_tools`, `agent_auth::oracle_tools_not_held`): a draft never inherits the saved oracle's tools. `oracle.test` of the saved file, `oracle.mark-read`, `oracle.restore` and `oracle.delete` are the owner's. An `oracle` card (slug and whole file) is pre-checked when filed and stored formatted, with its tools, the tools added and removed, `can_leak` (a credentialed tool with http) and warnings; accepting runs `oracle.save`; it never starts on its own.
- CLI (`crates/cli/src/oracle.rs`, workspace from `--workspace` or the session's `workspace_id`): `launchpad oracle list|show|history [--calls]|run [--cursor|--since]` (exit 0 True, 1 False, 2 Failed, 3 a CLI error, pre-check errors included), `test --file [--slug] [--json]` (pre-check, then a run on Home without records), `save|pause|resume` (admin) and `launchpad propose oracle`.
- UI (`web/src/features/schedules/Oracles.tsx`): Schedules → Oracles (`?tab=oracles&oracle=<slug>&view=…`, `_new` = New oracle): the list, and a page with Definition and Test (pre-check errors and type warnings at their lines, the call log and log of each answer), Tools (switches rewrite the header's `tools = […]` line, added tools highlighted, the leak warning), History, Used by and Versions; `GateFields` in the routine editor. Today's oracle details come from `OracleFailure.tsx`, so Today never loads the oracle page.
