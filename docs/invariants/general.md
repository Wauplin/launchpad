# General

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- Single user: no backward compatibility, versioning or migration framework; keep `state.db` schema changes simple. Removed config.toml and bot.toml keys keep loading (unknown keys are ignored).
- Linux (Ubuntu) is primary; gate OS-specific APIs. Agents and terminals run only on Linux (a Linux machine, a Local VM or Burst; `role::ensure_agent_os`, whatever the role): `daemon --role runner` and `launchpad connect` refuse elsewhere, and Home refuses pairing, approval and tunnels of non-Linux runners (`role::os_refusal`, shown in Settings → Home and runners). On a Mac, `packaging/local-vm.sh` creates a Linux VM runner. Home runs no agents and may run elsewhere. CI currently runs tests and release builds on Linux only.
- Crate layering: `launchpad-core` depends on no other Launchpad crate; the feature crates (`harness`, `channels`, `github`, `automation`, `setup`) depend only on the core, never on each other; `server` never depends on `api` or a feature crate. The core reaches the crates above it only through `harness::install` and `ext::Extensions`, both installed by `crates/cli`. Put new code in the highest crate that can hold it; move code into the core only when the core calls it.
- Phase 7 extensions need an owner-approved scope. The daemon owns harnesses and terminals; there are no session workers.
- Click only: every action is a visible button. The only gestures are pull to refresh on the phone's Today and Agents lists (`web/src/components/PullToRefresh.tsx`) and, on the phone's Chats list, swipe right on a conversation to uncover Archive, which archives only on a tap (two steps; `web/src/components/SwipeReveal.tsx`; the row's ⋯ keeps Archive). Keyboard shortcuts are limited to `Ctrl+F` in Files, `Ctrl+T`/`Cmd+T` for a new terminal, `Ctrl+K`/`Cmd+K` for Go to (outside terminals; the top bar's Go to button and More → Go to on the phone open it too), terminal clipboard and clear keys, normal text-editing keys, `Enter`/`Shift+Enter` in the session message box, `Ctrl+Enter`/`Cmd+Enter` in the launch composer's prompt (Launch, or its scheduled variant) and in the extension's private note boxes (Add private note), the top-bar field (Enter sends with its primary button: Ask on every page, Launch only in a workspace without a bot; Shift+Enter adds a line) and the find field, and `@`, `/`, `#` suggestions in prompts.
- No editor integration (buttons, settings or endpoints).
- Presets are user-defined only: keep the config default and first-start template empty.
