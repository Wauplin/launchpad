# Profiles, quota and costs

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- Profiles (`[[profiles]]` in config.toml) are the only way to run an agent; none are built in. Sessions store the profile ID, never environment values; missing IDs or changed harnesses fail visibly on resume.
- One quota monitor per subscription login, checks use the session's login. The logins are Home's vault logins (`quota::vault_key`), monitored on Home with its own copy of each (`vault::login_home`), never the machine's `~/.claude` or `~/.codex`. A profile without its own login uses the harness's default login (`vault::default_login`: the first by name, then id), the same one for its lease and its quota reading (`vault:default:<harness>`, resolved only on Home); runners receive the readings (`ToRunner::Quotas`, also at once when they connect, before any request) and send Home the complete readings of their running sessions (`quota::session_reading`, at most one per login every 15 s). Claude never uses the usage endpoint (a `setup-token` token gets 403) and is never polled (`claude_quota.rs`): readings come from sessions' `rate_limit_event`s and from a probe, a one-word `claude -p` with Haiku at low effort read from the same event, run on Home only when the reading is unknown, automatic work waits for it or a quota pause's resets passed (`quota::paused_wanting`), and the known reading does not confirm capacity; never while a used-up window has not reset; one at a time per login (`Gate`, shared with the owner's Refresh, which reuses a valid reading), at least 2 minutes apart and backing off 1 minute to 1 hour after failures; a failed probe keeps a still-valid reading. A complete reading confirms capacity for 10 minutes while both windows are under 80 % used, else 90 seconds, and never past a window's reset (`quota::valid_ms`).
- Automatic work needs fresh confirmed capacity (`quota::hold_reason`); the owner's messages and clicks, and an admin session's direct launches, session messages and card accepts, may start on best-effort protection. Automatic are: routine runs of every trigger (`crons::quota_hold`; an event run without it is skipped as missed; schedules and failure triggers wait up to an hour before they claim), scheduled launches and follow-ups, messages of hooks, channels and agents to a bot (`bots::quota_hold`, per thread: a hook or channel message waits in `queued_message`, an agent's is refused; a new session holds its prompt), cards a bot in auto mode starts (a launch holds its prompt; a message card without confirmed quota is not sent and waits for the owner's Start, its note saying why) and merge-conflict messages to the agent (refused with a notice, the owner's Fix merge sends them).
- Allow paid usage defaults to false and is never remembered. Exhausted quota holds input or pauses into Quota paused; continuing needs fresh confirmed capacity in both windows, never a reset time alone (null reset = window not started). Owner messages during a pause wait in the durable pending continuation and are delivered in order with it; Stop and Archive discard them.
- Cost and rolling spend limits apply only to harnesses reporting USD; reaching one refuses input, interrupts best effort and never resumes automatically. Home holds the spending ledger of every machine (`spend.rs`): runners, Burst jobs included, queue each cost increase for Home (`replica::Item::Spend`, counted once by its ID), Home sends its ledger to every runner (`ToRunner::Spend`: all on connect and after a config change, then each new entry), and runners check the rolling limits against it plus their own increases Home has not stored yet; Home starts no Burst job for a launch or message past a limit. Claude adds only increases of its per-process `total_cost_usd`. Terminal TUIs are outside quota protection.
