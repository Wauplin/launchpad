# Chrome extension

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- The Chrome extension panel is its own small UI: never import the app's Composer, SessionPane, router or phone shell; reuse only `lib/` helpers, pure store helpers, generated types and Markdown. The extension is a GitHub layer (marks inside github.com) plus a side-panel chat about any page; it never acts in pages: agent text goes into GitHub's own fields only on an Insert click, or by prefill (below), it never clicks or submits GitHub forms, and its only GitHub writes are the three confirmed ones below, through Home. There is no computer use (no browser grants, browser tools or native host). Only the service worker (`extension/src/background/`) talks to Home and Hugging Face and holds credentials (HF refresh token and device secret in `chrome.storage.local`, the access token in `chrome.storage.session`, both closed to content scripts); the panel and content scripts reach Home only through the typed runtime messages of `extension/src/shared/messages.ts` (sign-in, connection and settings requests only from extension pages; one dedicated request per Home route, each checking its input: there is no generic Home call). The Hugging Face token goes only to the Hub and to a Space's own address (`https://<name>.hf.space`): discovery asks `/_home/status` only of running Spaces of the signed-in account, and a Space of an organization is contacted only after the owner chose it. No Chrome notifications: the toolbar badge shows Today's count of the extension's workspace. The worker caches each page's context 30 s per page and workspace, drops it on relevant bus events (pushing the synthetic `ext.context` topic to the pages) and follows the workspace of the folder of the active tab's repository. The GitHub layer (`extension/src/content/github/`) takes the page kind from the URL; every insertion point is a named anchor in ONE file, `anchors.ts`, with two or three strategies (ids and data attributes, then ARIA, then text), whose health the panel's Settings shows ("3 of 4 work"); a broken anchor shows nothing on the page. Widgets are Shadow DOM hosts (closed roots, `widgets.ts`: `mount`, `chip`, `openMenu`, `h`) styled with Primer variables plus the teal accent and logo, built from text only (never page HTML), re-rendered idempotently after soft navigations (Navigation API, Turbo events, popstate, URL polling) and one scoped MutationObserver; IDs and numbers come from the URL and Home, never page text. Never call `.click()`, `submit()` or `requestSubmit()` on GitHub's elements. Insert and prefill, never submit (`content/github/insert.ts`): Insert is the owner's click on a Launchpad banner, card, box or the panel's This item; it writes into GitHub's own field (the conversation's comment box, or the open reply box of the review thread a `review_comment` reply answers; a closed thread box is only focused and scrolled to, never opened by a click) with `document.execCommand("insertText")` so Ctrl+Z undoes it (the native value setter plus an `input` event when the editor refuses), asks Replace or Add below when the box has text, and adds the attribution line after a blank line, visible and removable. Prefill (Settings → GitHub, off by default since the timeline shows suggestions, `ConnectionState.prefill`): the newest suggested comment for the conversation's box goes into it without a click when the box is empty, once per tab, keeping the focus and scroll position; it claims nothing until GitHub's form is submitted (then `inserted` and `posted-by-hand`), and an untouched prefill is taken out again when the suggestion is discarded or posted from Launchpad. Insert then records `suggestion.inserted` and only OBSERVES that form (capture-phase `submit`, GitHub's own submit buttons, Ctrl/Cmd+Enter in the box) to read the final text just before GitHub sends it, for `suggestion.posted-by-hand`; `suggestion.shown` once a banner was on screen 1.5 s. No worker request merges or sends; the only one that posts a suggestion is Post this comment (below). Ask on a comment, the sidebar box's main action (Insert reply, Continue, Review with agent, Draft a reply) and the panel send `bot.message` with a `github_refs` entry naming the item or the comment (`…#issuecomment-<id>`, `…#discussion_r<id>`, from the comment's anchor ID, never its text); these go with `item_thread`, so each GitHub item has its own thread of the bot (`ExtAgent.thread`); `github_ref_use.comment` keeps the comment a session was last asked about, so `ExtAgent.comment` places its live card under that comment, and the last bot used on the repository becomes its default. The panel (`extension/src/panel/`) has Chat (one thread of a bot, chosen in the picker with `bot.threads`, `main` by default; New conversation starts a new thread; the page snapshot of `page.ts`, read once on Send through `activeTab` and `scripting`, goes as an attached `page.md`), This item (GitHub pull requests and issues: the item's thread and its state, Continue opens it in Chat, the same buttons as the page, Insert through `TabCommand` to the tab's layer, and the fallback for broken anchors), Today (`panel/Today.tsx`: the workspace's unread notes from `GET /api/ext/notes/unread`, each opening its item on github.com, with Mark read and Mark all read, then Today's items grouped by filter, each opening its card in Launchpad; the header's amber count opens it) and Agents; the context menu's "Ask Launchpad about selection" only adds a quote to the panel's box (`QUOTE_TOPIC`, `quote.take`). Lists (`content/github/lists.ts`, `repoStrip.ts`, `rows.ts`, `target.ts`, `addRepo.ts`): one `rows` request for the visible rows (refetched when the set changes or on `ext.context`), at most one chip per row (needs you › working › a bot's report › commits to push), plus the notes tag (`ExtRow.notes`: teal "N new notes" while an agent's note is unread, quiet "N notes" after), and hover actions that never replace GitHub's controls. The extension adds nothing inside GitHub's repository tab bar (an extra element makes its UnderlineNav fold every tab into More); Local PRs show in the Code page strip and the Pull requests section, each Local PR unfolding its details (`localpr.detail`: description, commits, files) in place, and the strip's suggestions unfold too. Popovers and menus go into one fixed overlay host on `<body>` (`widgets.ts` `overlayRoot`), since list rows use `content-visibility: auto`, which clips a fixed element inside them. The notifications page (`content/github/notifications.ts`, page kind `notifications`, anchor `notification-rows`) puts the row chip, the notes tag and the hover Review with agent / Ask (⋯: Ask a bot, Draft a reply, Add to Launchpad) at the end of each row's repository line (`notificationSlot`; an unknown layout gets nothing), so rows keep GitHub's height; it only reads the list's links and never marks, archives or clicks anything there. The three GitHub writes the extension can start, Publish of a Local PR (`localpr.publish`: the same options and confirmation as Launchpad, the reviewed commit the dialog showed), Push to this PR (`branch.push-to-pr`: the branch commit the dialog showed; an agent's waiting ready card of the pull request, `ExtContext.ready_pushes` read from `launch_proposal`, also offers it under the agent's newest note in the timeline with the card's branch and commit, never the note's text, and the worker starts that card (`/ran`) after the push) and Post of a timeline entry (`suggestion.post` with the `actions` the owner left ticked under it, each run once after the text is posted, a follow-up never retried, after `suggestion.edit` when the owner edited the text: a comment, or a review's summary and each line comment's text, with Leave out per line comment; Home's `kept_comments` refuses a line comment that is not one of the draft's at the same place, so edits never move or add one), run only on a trusted click (`event.isTrusted`) of the owner: Publish and Push from the confirm button of their own dialog (the panel's This item: its own confirm step), Post this comment directly from the timeline entry's button, under the comment shown in full, through dedicated worker requests. Private notes (`crates/github/src/notes.rs`, table `item_note` on Home; `ExtContext.notes` of the extension's workspace, oldest first; `note.delete` the owner's) are a private timeline of an item, never posted anywhere: `launchpad note` (an agent's own write like a suggestion) appends a note each time, optionally carrying a suggested comment (`--suggest-file`, a record of the Suggestions created like `suggest comment`) and answering a note (`--reply-to-note`); `launchpad notes` lists an item's notes of the session's workspace (`GET /api/context/notes`, a narrowed list read) with each note's link (`notes::link`: the item URL plus `#lp-note-<id>`), which notes use to reference other notes; the owner's `note.write` (owner only) stores a note with `by_owner` and sends an owner message to each agent that wrote a note or suggestion about the item in the workspace (a bot's item thread, else the session; else the item's default bot), a failed delivery never failing the note. The extension draws each note and each note-less suggested comment inside GitHub's timeline at its moment (`content/github/timeline.ts`, `timeline-items` anchor; above the comment form, else under the description when no item is found), with the owner's private note box above GitHub's comment form (`comment-form` anchor), Markdown built from text by `markdown.ts` (GitHub references and note links as short links through the pure `refs.ts`; a link to a note of the page scrolls to it and marks it, also when the page opens at `#lp-note-<id>`; each note lists the notes that reference it), and lists them in the panel's This item. An agent's note is unread (`ItemNote.seen_at` None; `launchpad notes` lists an item's notes of the session's workspace (`GET /api/context/notes`, a narrowed list read) with each note's link (`notes::link`: the item URL plus `#lp-note-<id>`), which notes use to reference other notes; the owner's own are seen when written) until the owner's `note.read` (`POST /api/notes/read`, one item or the whole workspace): the timeline calls it once the item's page was visible in a focused window for 1.5 s, and keeps a New tag on those notes while the tab stays on the page. The agent view (`content/github/agentView.ts`) is a read-only drawer on the page with an agent's turns from `session.events` (`chatRows`: the message, the answer as Markdown, the step titles folded), refreshed every 5 s while open, closed on navigation; Stop and the full trace stay in Launchpad. Files changed (`content/github/files.ts`): Ask about these lines reads GitHub's own line selection (the `#diff-<sha256 of path><L|R><n>` fragment, else its highlighted cells) and sends `bot.message` with `selection`; the answer (the bot's last message after that message, by its key) shows under the lines with Turn into line comment (the bot's suggested line comment there, as its ledger part, else the answer without a ledger record). A suggested review's line comments are ghost comments under their lines (dashed teal) with Add to my review, which fills GitHub's own line comment form (`line-form` anchor) and records `inserted` for that part (the owner then clicks GitHub's Add single comment / Start a review, observed as `posted_by_hand`), and Dismiss (`suggestion.dismiss-comment`). A closed line form is never opened by Launchpad: the line is scrolled to and its fill waits two minutes for the owner to open it with GitHub's +. Over GitHub's Review changes dialog, Insert summary fills only its text field; the event radios and submit stay the owner's (the suggested event is shown as text). Launches from GitHub (`launch` worker request: Investigate and Check with an agent read only, Fix in a Local PR ending in a Local PR, with the item in `github_refs`) are the owner's one-time launches in a Git folder of the extension's workspace with a profile chosen in the popover (the worker reads `GET /api/context/profiles`, never `/api/config`, and passes on only id, name, CLI and billing). Text read from the page (titles) is shown in our popovers only, never sent to Home or an agent. A line comment's ```suggestion block shows as a diff (`content/github/suggestionDiff.ts`, pure line and word diff in `lineDiff.ts`): the content script reads the commented lines from `https://github.com/<repo>/raw/<head>/<path>` (same origin, the owner's session; the PR's head ref when the suggestion has none), keeps them per repository, head and path for the page's life, only shows them, and falls back to the plain block. Keep the extension ID/key (`extension/public/manifest.json`), the daemon's origin allowlist (`EXTENSION_ID` in `crates/server/src/auth.rs`) and the Space gateway's (`EXTENSION_ORIGIN` in `deploy/hf-home/gateway/proxy.py`) in sync.
