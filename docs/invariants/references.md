# References

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- Every Launchpad object has a link and a short ID (`launchpad_core::refs::LpRef`: session and message, chat and message, channel or DM and message, folio page and section, topic, bot, Local PR, folder, card, oracle, routine, note). `refs::parse` reads both forms (`lp:<kind>/…` and a window address on any host, older addresses included), `id_text` and `path` write them, and `web/src/lib/refs.ts` builds the same strings; both check `web/tests/refs/cases.json` (`cargo test shared_cases_round_trip`, `pnpm test:composer`). Only Home parses pasted text (`GET /api/refs/resolve` for the owner's window, `GET /api/context/ref` for agents, a `Names::Listed` read so the workspace is forced, never from an oracle) and `refs::resolve` answers unknown, malformed and out-of-workspace objects with the same words (`refs::UNKNOWN`). As context, references are never their text: `MessageContext.refs`/`LaunchSpec.refs` (chips) and the references the text contains (`refs::scan`) are resolved by Home against the receiving session's workspace (`refs::resolve_context`, from `runners::deliver`, `runners::launch_placed` and the start preview) and the prompt gets one read command per reference (`refs::notes`); a runner drops `refs` of input Home did not relay. `launchpad ref read` answers a bounded excerpt (the target message with a few around it, never a whole transcript). Copy link on messages (`ChatMessage onCopyLink`, the session trace), rows (`copyRefLink`) and folio sections; links open in-app through the navigator the shells install (`setRefNavigator`, Markdown links and `lp:` IDs in text), and `?msg=` (agents, chats, channels) and folio `?section=` scroll to the target, loading older pages first.
