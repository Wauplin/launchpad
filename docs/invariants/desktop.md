# Desktop companion

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- `desktop/` (`launchpad-desktop`, GTK 4, Ubuntu 26.04 GNOME on Wayland) is a separate client of Home like the Chrome extension, in its own Cargo workspace: root crates never depend on it, and Home never depends on it or opens windows for it.
- It talks to Home with its device secret in `X-Launchpad-Device` plus `X-Launchpad-Client: desktop/<version>` and never an Origin, follows the companion's own workspace (`ws=` on every address it opens) and checks `GET /api/version` before anything else. Its HTTP client follows only same-origin redirects (reqwest keeps custom headers across hosts), and it reads profiles from `/api/context/profiles`, never `/api/config`.
- Secrets live only in the Secret Service keyring (the device secret, the Hugging Face refresh or pasted token); settings, logs (redacted), URLs, notifications and the clipboard never hold one; without a keyring it refuses to link.
- Its writes are bot messages, answers to a question (never a permission request) and launches; a launch starts only from the quick launch's Launch button or Ctrl+Enter there; the composer hand-off writes Home's launch draft with its revision and never overwrites the browser's text. It never posts to GitHub, approves, merges, publishes or enables paid usage.
- Updates: it only reads Wauplin/launchpad's public releases; an update installs only on the owner's click in its menu (downloads only from that repository's release URLs, into a fresh 0700 folder under `$XDG_CACHE_HOME`), after the `.deb`'s SHA-256 matched both GitHub's asset `digest` and the published `.sha256` and `dpkg-deb -f` named `launchpad-desktop`, `amd64` and the release's version; PackageKit (polkit) or `pkexec` installs it. The global shortcut binds through the GlobalShortcuts portal at every start (GNOME lists only a session's own shortcuts and asks for consent once per app ID); the GNOME custom-shortcut fallback is written only on the owner's choice, touches only its own entry and replaces the portal's binding while it is set.
