# Topics

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- Topics are workspace collections on Home (`topics.rs`, tables `topic` and `topic_session`), independent of runner-replicated session records. Membership edits never send input or change session status; archived sessions retain membership. Bulk edits validate every session against the topic's workspace before one transaction. A session shows its topics as one chip in its meta line (`SessionTopics`: names link to `/topics/{id}`, × removes membership with Undo, the same field finds or creates one); topics never take a row of their own in the session pane or the Agents list header. `/api/topics…` is Home-owned and owner-only; scoped agent reads use `/api/context/topics` (`launchpad topics list|show`). Topic selections freeze their trace IDs and event cutoffs on Home at dispatch, then expand without recursion and deduplicate overlapping traces. Launch and follow-up context inherit source memberships in the receiving workspace; membership remains independent of context. A launch with direct traces groups its sources (`topics::group`): it inherits their topics and sources without one join them, or Home creates one topic for all of them (`auto_session` = the new session) whose name the new session's runner generates once (`titles::name_topic`, claimed before the request, never retried) and returns only through `LaunchSpec.topic_naming.name` of the replicated record; Home applies it only to that session's `auto_session` topic (`topics::named`), sets `topic_naming` itself (never from a request) and deletes the topic when the launch leaves no session (`forget_auto`); an owner rename wins.


- Item links: `launchpad link --repo owner/repo --number N --session-id ID` links only the calling agent’s session (optional `--comment-url`). Item references and suggestions automatically join the session’s workspace topic `repo#N`. Local PR bodies store issue associations as `Fixes #N` / `Closes #N` / `Resolves #N` for the folder repository; the extension shows these on the issue. Agents have no general topic write permission.
