# UI rules

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- Every action a button, a card, the CLI or the admin rules name is one entry of the action list (`crates/core/src/actions.rs`: route, input, confirmation, effect, access, card kind, undo). Add new actions there; buttons use `ActionButton` (it confirms when the action has a confirmation) or `runAction` (`web/src/lib/actions.ts`); run `gen-types` after changing the list.
- Build pages from `web/src/components/ui.tsx`: `PageHeader`, `Tabs`, `FilterChip` (narrows a list), `Choice`/`Choices` (the options of a setting, styled like the profile picker), `ConfirmButton` (every destructive or GitHub action; never `window.confirm`), `Loading`/`Empty`/`ErrorState` with `humanError`, `Badge`/`Token`, `StatusBadge`, `Count`, `RowActions`, `IconButton`, `SettingRow`. Text fields and selects use `field-input` with its default height and 13 px text (only `font-mono text-[12px]` for code values); buttons use `btn`/`btn-sm`/`IconButton`. Use semantic color tokens and sprite icons. One primary button per region.
- Sizes (tokens in `web/src/styles.css`, checked by `pnpm ui-check`): text only 11/12/13/15/18 px as `text-[Npx]` (Tailwind's `text-xs`, `text-sm`… are removed from the theme); corners `rounded-control` (6 px: buttons, fields and message boxes, menu items) and `rounded-card` (10 px: cards, panels, dialogs), `rounded`/`rounded-full` for marks and pills; icons 12 px inline, 14 px in icon buttons, 16 px in navigation (phone bar and tab icons may be larger); gaps from the spacing scale (`gap-1`, `gap-1.5`, `gap-2`…), never `gap-[Npx]`; page bodies `max-w-page` and reading columns `max-w-text`, left-aligned under the header with its `px-5`; no fixed hex or Tailwind palette colors (`red-600`…) outside the theme; never force an icon button's size (`size-…!`). Justified exceptions go in the script's allowlist.
- Action group: a list row or card shows at most one visible button, its main action as an outline button with a label in a right column of a minimum width (one exception: a finished or failed agent's Today row also shows Archive after it, on a laptop only); everything else goes in ⋯ (`RowActions`, built on `.lp-row-more`: shown on hover and keyboard focus, kept while its menu is open, always visible on touch screens; `MoreMenu` alone for a row or card without a main action). Menu entries are `MenuItem`s, actions of the action list use `ActionMenuItem`, and a confirmation (`ConfirmButton`) goes last in a `MenuSection`. The only filled button of a region is its single most important action.
- Icon-only buttons (`IconButton`) only in a toolbar where every button is icon-only, never mixed with text buttons (except ⋯, the menu of an action group); each has a tooltip and an `aria-label`; one size: 28 px laptop, 44 px phone, 14 px icon. Exception: the arrow after the "…" of a cut text (an agent's last message in Today) that shows the full text inline.
- States use `StatusBadge`, one color per meaning: blue running, amber needs you (question, quota paused), green Done (an unseen Done adds an amber dot, never an amber pill), red failed or interrupted, grey idle, stopped or archived.
- Conversations (bot chat, bot channels and DMs) draw every message with `ChatMessage` (`web/src/features/chat/Message.tsx`): all senders on the left with mark, name and provenance tag, the bubble by whose words they are (yours grey, the bot's outlined, other senders' dashed with "not from you"; a message from one bot to others of a conversation, and an answer back to the asking bot, reads "A to B and C" with every name in its identity color, outlined, with thin `edges`: the sender's color left, the recipients' right); steps, receipts, deliveries and wake/sleep lines stay outside bubbles. A bot's mark and name use its identity (`BotAvatar`: its DiceBear bottts avatar cached by Home, `GET /api/avatars/bottts`, on its color, the initial as fallback; `botTone`/`botInk`/`botEdge`; `lib/identity.ts`, bot.toml `avatar_seed` and `color`, one of `IDENTITY_COLORS` kept in step with `crates/core/src/bots.rs` and tokens `--color-id-<name>`; pass the bot's `id` when known) everywhere it shows; never color alone.
- Counts use `Count` (sidebar, tabs, chips, phone tab bar): an amber pill when the count needs you, a plain grey number otherwise.
- Dates use only `web/src/lib/format.ts`: `ago()` for past moments ("5 min ago", "yesterday", "Oct 3"), `age()` for the compact form in dense lists, `when()` for exact or future moments ("today 15:00", "Fri 7 Nov, 03:00", in the locale's clock); `time()`, `day()` and `month()` when a label needs only one part ("14:02", "Oct 3", "November"). Never `toLocaleString` for dates, never seconds, no year for the current year; callers never add " ago". Crons read as words (`describeCron`: "Every day at 03:00") with the raw cron in a tooltip.
- Page headers: every laptop page uses `PageHeader` (`SettingsPage` builds on it): the title without an icon, a meta line of facts (counts, sync state, never the workspace name alone), actions on the right and tabs under it; headers and page bodies share the 20 px side padding (`px-5`). A top-level page has no breadcrumb of its own name; a detail page's breadcrumb names its parents (Local PR: Folders / folder; bot, channel or DM: Bots; Settings page: Settings). Remote issues and pull requests have no page: their links open github.com.
- Words: Launch (start an agent; Start only for proposals), Delete (data) and Remove (only out of a list), Pull requests, Connections (outgoing webhooks and incoming hooks; Channels are bot channels), Search in folder.
- Page explanations go in `PageHeader intro` or `SettingsPage intro`: shown on the first visit on this device (`launchpad.intros-seen` in browser storage, never config.toml; the demo keeps them in memory and never writes it), then behind ⓘ next to the title. One explanation per page; a list never repeats the same paragraph on each item, and cards and side panels hold no help paragraphs. Keep the meta line for facts.
- Laptop columns resize through one component: a list or side column gets its width and divider from `useColumn(name)` (`web/src/components/ResizeHandle.tsx`; names, defaults and bounds in `web/src/lib/columns.ts`; widths per device in `stores/columns.ts`, shared by every page showing that column), and a right-hand drawer uses `SplitView`; never a fixed `w-[Npx]` list column with its own drag code. Phones get no divider.
- Virtualize every long list, memoize row components, use `useFlushSync: false` and prefer fixed row heights (WebKitGTK performance).
- Keep heavy imports out of `router.tsx`, `main.tsx`, both shells and the sidebar; other routes load lazily.
- The phone shell (`web/src/mobile/`) reuses feature components with `usePhone()`; never fork features. The phone bar shows the section title on a tab page, with the page's primary button and ⋯ on its right (`PhoneBarEnd`; a tab page adds no row of its own for them or for a count), or ‹, the title and the page's ⋯ or ⓘ on a detail page (`PhoneBar` or `PhoneHeader` with `onBack`, `web/src/mobile/PhoneHeader.tsx`, one per page); a page never draws a second title bar on the phone (no "All settings" or "Close panel" buttons). On the phone, Android back and ‹ do the same thing: close the topmost overlay, else go one page back (`web/src/mobile/back.ts`). Every overlay (menus, sheets, the composer, full-screen and Reply modes, an opened Today card, the Files tree, the image viewer) owns exactly one history entry through `useBackClose` (`Popover` and `Sheet` have it built in); detail views keep their state in the address (`?session=&view=`, `?thread=`, `?note=`, PR `?tab=` and `?file=`); switching between siblings (tabs, filters) replaces the entry; ‹ never adds an entry (`phoneBack(parent)`, `useBack` for pages without a single parent, `useLeave` for pages that add their own entries, like Files). Bottom tabs replace the entries above Today, and a cold start on another page puts Today and the page's list under it. Typed text never dies with back: editors keep drafts (`web/src/lib/keptDraft.ts`, or Home's review state) and say "Draft kept"; the bot chat's message box keeps its text the same way; the demo keeps drafts in memory. Phone Today rows show the title on up to two lines and one one-word outline button of one minimum width, without its icon; a tap on the row opens the other actions. Keep 44 px touch targets (chips, choices, fields, icon buttons, labels around checkboxes; styles.css enforces them over forced sizes). Phone fields are 16 px through an unlayered rule in styles.css, so iOS never zooms on focus; never set a field's size on the phone elsewhere. Phone Settings sections are flat (one border level). Phone toasts sit under the top bar, never over the tab bar. When Home is framed by its Space page on huggingface.co (`hfCorner` in `web/src/lib/phone.ts`, class `lp-hf-corner`; `?hf-corner=1` forces it), the Hub's floating button covers the bottom-right corner: keep controls that can reach the bottom edge out of it (the tab bar's empty fifth slot, the `lp-hf-corner` rules in styles.css). Keep the desktop layout unchanged at every zoom position (100–150%, default 120%, per device).
- Phone tabs: Today, Chats (`/chats`: the Chats list of the laptop, full width, with New chat in the bar opening the tiles; its count is `useChatsNeedCount`; a second tap opens the last chat or channel), Agents and More (`/more`: the other pages with their state; its count is what needs you there). A bot's session opens the bot's chat at its thread from Today and Telegram; its trace stays in Agents (Open in Agents), whose rows open the trace and whose session bar links the bot. The workspace sheet lists only workspaces with their counts. Phone Settings opens every Settings page, like the laptop: the same groups as the laptop's Settings sidebar (`settingsPages`; device controls, zoom, theme and layout, are the page This device → Appearance, `/settings/appearance`) and the setup checklist; no page is laptop-only. On the laptop `/settings` opens the Workspace page. Settings → Onboarding on the phone explores the demo (`phone:explore`, with a strip that has Exit demo); only the guided tours stay on the laptop. The phone session page has a bottom bar with Reply and the main action, or Merge into the base branch when it is safe; Reply replaces the bar with the message box (Hide brings it back), so no other action sits above the keyboard. Archive shows an Undo toast (`session.unarchive`, from the `UNDO` list in `web/src/lib/actions.ts`). The phone status button warns about connection, runners (refused, outdated or offline), quota, spending and the GitHub rate limit, and its sheet says why; it sits in the bar of every tab page, and a detail page's bar shows it only while it warns.
- Phone keyboard: the tab bar hides while a text field has the focus (read again from `document.activeElement` on each tap and viewport change, so a field that lost the focus silently never hides it for good). While the keyboard is up, and always on Terminals, the shell is pinned to the visual viewport (iOS Safari ignores `interactive-widget=resizes-content`), and a window scroll the browser left behind is undone once the keyboard closes. A message box's Send button keeps the focus in its field (`keepFocus` in `ui.tsx`), and the field turns read-only, not disabled, while a send runs, so one tap sends and the keyboard stays open.
- Theme, zoom and layout are device-local (browser storage), never in config.toml.
- Workspaces: every folder belongs to exactly one workspace (`project.workspace_id`). A window shows exactly one workspace, never all of them: the workspace menu at the top of the sidebar (laptop) and the workspace sheet (phone) show other workspaces as counts only. There is no default workspace: the owner names at least one in the setup's Workspaces step (adding or cloning a folder waits for it); Home refuses to delete the last one, and deleting a workspace deletes its bots (`workspace::delete`, refused while one works); runners never create workspaces and wait for Home's. Adding, cloning or creating a folder requires a workspace; a repository in two workspaces is two folders. Workspaces are also a boundary for agents (see the Launchpad CLI rule). Sessions, schedules and crons belong to a workspace only through their folder or repository; repositories without a folder belong to no workspace. Every narrowed list, count, `#`/`@` suggestion and message-context picker uses the `useScope()` predicates, except Today, which uses the workspaces Home resolved for each item with the same rules. Settings has two parts: **Workspace** (`/settings/workspace`, the window's workspace, its name in the meta line; its bots, its own Telegram bot and chat, its tools) and **Launchpad** (shared; Connections points to Workspace for Telegram). Notifications name their workspace and open it.
- Demo mode (`web/src/demo/`) answers every request in the browser; never call the real daemon or write browser storage from it. A new major feature updates its tour chapter (`web/src/onboarding/chapters/`), demo fixtures and handlers, and keeps `data-tour` anchors (`pnpm test:tour` checks them).
- Setup: Home's setup page (`/setup`, `HomeSetup`, or the Space gateway's) asks for a workspace, Home's GitHub login, a profile with its login in the vault, the agents' Git identity, where agents run (Burst, or a runner with the command that installs and pairs it) and a first folder (Clone or New plain folder). A runner's checklist (`setup_checklist.rs`, in its own window) only reads: Home link, jail, network capture, agent CLIs, vault logins and Git identity; a missing part shows a fixed command to copy, and Launchpad never runs it (no setup terminals). Never overwrite an existing Git identity, credential helper, SSH key or harness login, never run package managers automatically.
