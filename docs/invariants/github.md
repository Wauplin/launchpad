# GitHub

The design invariants every change in this area must keep. Read this page before changing the area, and update it in the same commit when a rule changes or a new one appears. [AGENTS.md](../../AGENTS.md) keeps only the cross-cutting rules; index of all areas: [README.md](README.md).

- github.com (plus the extension) owns GitHub notifications, issues and pull requests: Launchpad never caches, polls or renders them (no Inbox, no item pages or lists, no review requests in Today, no GitHub routine trigger, no image proxy). GitHub is read live, only when a feature needs the answer, and no response is stored on disk or in memory (request coalescing is fine; storing payloads is not); there is no background GitHub poller, except the reconciliation of published, unmerged Local PRs (`predrafts::sync_published`, every 30 minutes: one read of each one's pull request, keeping only the merge result in the record). Every link or button about a remote issue or PR opens github.com (folders link to the repository's pulls and issues there). At start Home deletes a leftover `cache.db` and `<data_dir>/images` and drops the old Inbox tables. Live reads: `--reply-to` resolution, whether a suggestion's item is a pull request (for pull-request-only or issue-only actions), an agent's CI approval (the pull request, its files and waiting runs), a published Local PR's pull request (`predrafts::sync_github`, `link_pr`), Post's head check, ledger confirmation, diff selections, the owner's private note (the item's kind and title for the agents' message), composer `#` suggestions (GitHub search per query), Clone from GitHub suggestions (the owner's recently pushed repositories); launches and messages with `github_refs` only name the item (repository, number, URL, comment anchor) and the agent reads it with its tools.
- GitHub paths built from a route or a body take only valid owner and repository names (`github::valid_name`: GitHub's characters, never `.`, `..`, `/`, `%` or empty); `GitHub::request` refuses dot segments, also encoded, and an invalid `/repos/{owner}/{repo}`.
- Agent reviews post as they are (summary and line comments in one review) from their own card (`suggestion.post`), with their `--merge`/`--run-ci` follow-up, and suggestions with their actions (`Suggestion.actions`, `ItemAction`: close with an issue's reason or as a duplicate, reopen, request reviewers, ready for review, convert to draft, update branch; flags `--close [completed|not-planned]`, `--duplicate-of`, `--reopen`, `--request-reviewers`, `--ready-for-review`, `--convert-to-draft`, `--update-branch` of `suggest comment|review|action` and `note`), run once in `ItemAction::rank` order after the text is recorded as posted: the owner's Post sends the actions left ticked (`actions`; absent, the agent's; the older `close` adds or removes the close, and a stored `close` reads as a close action), failures shown on the card and never retried. An action-only suggestion (kind `action`, `launchpad suggest action`, or `note` with action flags and no `--suggest-file`) has no text, no ledger part and no Insert. Never create GitHub pending reviews. Posting claims the suggestion before the write, records success before follow-ups and never retries an uncertain publication or follow-up. Local PR line-note locations are records, separate from editable text.
- The extension's page context (`crates/github/src/ext.rs`, routes in `crates/api/src/ext.rs`, types `Ext*` through gen-types): `GET /api/ext/context?url=&workspace=` (page kind from the URL, folder by remote with relation origin/upstream/fork, agents, suggestions with a review's line comments (`ExtLine`, each with the owner's last ledger step), private notes, Local PRs, followed branches "Not on GitHub yet" with the last push error, agent branches ready to push (`ExtBranch.push_ready`: an agent branch of the item that is not followed yet, with `ahead` commits since the agent started; Push checks fast-forward and fork permission on GitHub at the click), Today item IDs, default bot, and `login`, the owner's GitHub login once Home has read it) `GET /api/ext/rows?url=&items=` (row states of a list page: numbers on Pull requests and Issues, or `owner/repo#number` on notifications; each row with its agents, suggestions, Today IDs, folder, newest report, the followed branch with commits GitHub lacks and its agents' notes with the unread count) and `GET /api/ext/notes/unread?workspace=` (items with unread agents' notes) answer from Launchpad's own records only, never a GitHub call, in one quick request; each answer is narrowed to the folder's workspace, else the workspace asked for. Reports are read straight from state.db (`launch_proposal`), since `github` never depends on `automation`. Home-owned (runners forward them), closed to agents. Launches and bot messages that name GitHub items are recorded in `github_ref_use` (`ref_use.rs`, pruned after 180 days): the agents of an item and the last bot used on a repository. The default bot is the folder's `bot` (`folder.set`, Folder → Bot on GitHub), else the last bot used on the repository, else the workspace's Ask bot (`bots::ask_target`). Review with agent on a repository's lists remembers its bot and preset per repository (`github.review-choice`, table `repo_choice`, `ExtDefaults.review`); presets go to bots as text before the message (presets with `bots = true`, `ExtContext.presets`). Add to Launchpad is `folder.clone` (Clone from GitHub, owner only); Ask without cloning is a bot message naming the repository or item (`github_refs`), so a bot without a folder answers in a temporary folder of the workspace.
- Diff selections (Ask about these lines): a launch spec or a message context may name `selection` (`DiffSelection`: repo, number, path, side, start, end, head; at most 400 lines), a reference, never page text. Home reads the lines when it sends the launch or message to a runner (`runners::launch_anywhere` and `runners::deliver` through `ext::Extensions::selection_lines`: the PR's files read from GitHub at delivery, never cached, with a first line naming the head when it moved) and puts them in `lines`, replacing whatever a request said; a message or launch of another bot or agent may name only a repository of its own workspace (`scope::repo_outside`, since Home reads with its own GitHub login); a runner clears `lines` of input Home did not relay. `compose::render_prompt` adds the reference to the context and the lines fenced and labeled as untrusted text from the pull request's author, plus how to answer: a line comment worth posting goes into a suggested review with exactly one line comment on those lines, which the extension inserts as that line part (`line:<path>:<line>:<side>`) of the ledger.
- `branch.push-to-pr` (`POST /api/items/{owner}/{repo}/{number}/push-branch {branch, head}`, owner only, ready-card-able, `launchpad_github::ext::push_to_pr`): the owner's Push to this PR of an agent's Launchpad branch (`lp/…`) of a folder of the PR's repository. Home reads the PR on GitHub (open; its branch repository: the folder's own, the owner's fork, or a fork whose author lets maintainers edit, else refused), then `home_git::push_to_pull_request` checks under the mirror's lock that `head` (the commit the owner saw) is still the branch's tip, fetches the PR branch again and pushes only a fast-forward of its head, never forced; then it follows the branch (`git_follow`, like a launch with Push to PR), so the agent's next commits go there too, and tells the agent. Never retried; a refused push is shown, never recorded as a follow.
- Attribution origin (`attribution::Origin`, `with_origin`): the attribution line on GitHub ends inside its italics with `, posted automatically` (an agent's or bot's own write: the proxy and token relay sign its `gh`/API calls, an agent's `launchpad pr publish` (the route's `AgentSession`), When done = Draft PR or Open PR, Claude Code's `attribution.pr`) or `, posted manually` (the owner's click: Suggestion Post, Local PR Publish and Publish all from a window or ready card, the extension's Insert and prefill that the owner submits). Home decides it from the caller, never from the text; signing replaces any trailing attribution line of either origin, so an agent cannot claim a manual post. An owner asking an agent to post is still automatic. Outbox messages keep the line without an origin. The contained instructions name the base line and tell agents never to add it.
- Thread replies: a GitHub suggestion's target may name `reply_to` (`ReplyTo`: kind `issue_comment` or `review_comment`, GitHub's comment ID, author and URL), set only by `launchpad suggest comment --reply-to <issuecomment-<id>|discussion_r<id>|comment URL|PRRT_ thread ID|bare ID>` and resolved on Home by reading the comment from GitHub (`suggestions::resolve_reply`: a bare ID tries an issue comment, then a review comment; a `PRRT_` thread takes one GraphQL query). Only comments reply. Launchpad's Post sends a review-comment reply through GitHub's reply API (`items::reply`, into that thread) and an issue-comment reply as a new comment starting with `ReplyTo::prefix` (a quote line linking the comment and mentioning its author); the extension's Insert uses the same text (`ExtSuggestion.text`) plus the session's attribution line (`ExtSuggestion.attribution`).
- Feedback ledger (`crates/github/src/ledger.rs`, table `suggestion_ledger` in state.db on Home): one record per part of a suggestion (`body` or `line:<path>:<line>:<side>`), created with the agent's original text when the suggestion is created, then events `shown`, `inserted`, `posted_by_hand`, `confirmed`, `unconfirmed`, `posted_by_launchpad`, `dismissed`, `discarded`, `outdated`, with the final text, the edit size (`EditSize`: characters and words changed, ratio kept, attribution left out), whether the attribution line was kept and the posted URL. Capture only: nothing reads it to decide anything (a later Feedback view and gardener will). The owner actions `suggestion.shown`, `suggestion.inserted`, `suggestion.posted-by-hand` and `suggestion.dismiss-comment` (`/api/suggestions/{id}/…`, `GET /api/suggestions/ledger`) record what the extension saw; agents never reach them. `suggestion.inserted` claims the suggestion like Post (status `inserted`: Launchpad's Post refuses and the card says Inserted on GitHub; Insert again and Discard stay possible), `posted-by-hand` makes it `posted_by_hand` (handled in Today). A posted-by-hand claim is only a claim: Home confirms it when `ledger::confirm` (run 20 s, 2 min, 10 min and just after an hour after the claim; a Home start schedules these checks again for every pending claim, `ledger::resume_checks`) reads the item's issue comments and, for line parts, review comments live from GitHub (`since` the insert) and finds one by the owner's login (`GET /user`, held in memory per process), created after the insert, keeping at least 85 % of the claimed text; without one within an hour it becomes `unconfirmed` and never counts as feedback. No marker is ever added to posted text. Post and Discard write their ledger events too; Post reads the PR head live and marks line comments `outdated` when it moved since the review.
