Launchpad · UI/UX review · October 10, 2026 · commit 05f96f5

Make the "what needs me now" loop obvious, and remove the chrome around it

Launchpad already has the right features. The friction is in finding the next thing to act on and in fixed-width chrome that competes with the work area. Below are 12 ranked changes, each with evidence from the code, a concrete suggestion and, where useful, an interactive sketch. All sketches use fake data.

Method: read every view in web/src and drove the dev build in headless Chrome at 1600×1000 and 1280×800 with the default 120% zoom. Not reused: earlier reviews. Not published: live screenshots or personal data.

1 · A "Needs you" group, and Done that can be seen

High · The main loop is "an agent finishes → I read → I reply or archive". Today, the list does not support this loop.
  • The group order is Cron, Scheduled, Running, Quota paused, Stopped, Interrupted, Failed, In terminal, Done. Done, the group that waits for you, comes after 8 others. features/agents/AgentsView.tsx:158
  • Done is sorted by status_since ascending, so the oldest Done session is first. AgentsView.tsx:145
  • Done has no "seen" state: a session finished 8 days ago keeps the yellow sidebar badge and the bold status bar count. When the badge is always on, it no longer tells you that something is new.
  • A row repeats its group name ("DONE" header, then "Done 8 d" on every row) and shows the project and cost. It does not show what the agent said last, which is what you need to triage.
Suggestion. Keep the existing isDone predicate. Add a seen_at timestamp on the session (set when the Summary or Trace of a Done session is shown in a focused window, like the presence report already does). Then:
  • Needs you (always first, expanded): open questions, then unseen Done, newest first, then Failed/Interrupted that were not seen.
  • Running, Quota paused as today.
  • Done (seen), newest first. Stopped/Interrupted/Failed/In terminal stay below. Cron and Scheduled move to the bottom, collapsed by default, with the next run time on the header line.
  • The second line of a row shows the start of the final message (one line, plain text). The status badge only appears when it adds information (Question, Failed, Quota paused).
  • The sidebar and status bar count unseen items. Project markers use the same predicate.
Sketch · Agents listIn Suggested, open a row then another: the one you read becomes seen and the badge decreases.

Bulk cleanup completes the loop: "Archive seen Done older than 3 days" as one button at the bottom of the Done group.

3 · Composer: prompt first, options in one line

Medium · Field order is harness (2 rows of 6 chips with variants), Project / Run in, Prompt, Context (with a 2-line hint), Recent contexts, Presets, Model / Effort, Cost limit, Repeat, Start, Prompt preview, then a footer with 3 explanation lines. Launch stays disabled until the preview request returns (launch/Composer.tsx:204). Most launches change only the prompt and the project.
Suggestion.
  • Order: Prompt (autofocus, larger), then Project ▾ · Run in ▾ on one line, then attached context chips with "+ Add" (one popover: Project, GitHub link, Agent trace, Recent).
  • Then one summary line that shows every option as a token: Claude Code · opus · xhigh · worktree · now · once · subscription only. Clicking it opens the options panel. Tokens that differ from the default use the warning color (paid usage on, a cost limit, a delayed start, a cron).
  • The harness and variant picker becomes the first token: 6 chips in 2 rows are the biggest block in the drawer today, but you change them rarely.
  • The prompt preview becomes a "Preview prompt" button (popover). Launch does not wait for the preview; the server already renders the prompt.
  • The footer keeps one line: "Open after launch" and Launch. The quota text moves into the paid-usage token tooltip.

4 · Session header: one action that depends on the state

Medium · The action row shows Summary | Trace, Open in terminal, Terminal, Files, Add trace as context, Git, Open in editor, Archive and ✕, all with the same weight (agents/SessionPane.tsx:243-296). The action you need most is either missing (Reply, Review diff) or hidden: Stop is an unlabeled icon among the other buttons (SessionPane.tsx:248). The model · effort chip appears in the header and again in Summary → Run. "Git" opens a raw fatal: not a git repository in folders that are not Git repositories. "Files" leaves the session for the code route without a way back.
Suggestion.
  • Tabs: Summary · Trace · Changes. Git becomes a third view instead of a toggle button. Hide it when the folder is not a Git repository.
  • One primary button that depends on the state: Running → ■ Stop (labeled, danger style). Question → Answer. Done → Review changes if files changed, otherwise Archive. Stopped/Failed → Resume. In terminal → Re-attach.
  • Two fixed secondary buttons: Terminal and Editor. Everything else goes under More ▾: Open in TUI, Files, Use trace as context, Archive (when it is not primary), Pin.
  • Remove the model chip from the header line; keep it in Summary → Run. Keep the warning badges (Paid usage on, cost limit reached) because they are exceptions.

5 · One "To publish" list for agent drafts and pre-draft PRs

High · By design, everything an agent prepares for GitHub waits for your click. However, nothing tells you that it is waiting:
  • Suggestions (launchpad suggest comment|review) are only shown at the top of the target PR's Conversation tab (github/ItemView.tsx:109). They are not shown on Files changed, in the Inbox, in the session that wrote them, or in any count.
  • Pre-draft PRs are only listed in the project's Pull requests tab and as a "Pre-draft PR" link in the session. There is no global list, so you need to remember which project has one.
Suggestion. Add a sidebar entry To publish with a count, under Agents. It lists both kinds, newest first. Each row has the target, the agent session it comes from, and two buttons: Review & post (opens the PR or the pre-draft page with the draft expanded) and Discard. In the session Summary, add a Next step "This agent drafted a review on #5102 → Review & post". On every tab of a PR page, show a slim banner "1 agent draft waiting".

6 · Inbox: triage in one click per item

Medium
  • Done, Unsubscribe and Read/Unread are only visible on hover (inbox/InboxView.tsx:72). This breaks the "every action is a visible button" rule, and "Done" is the most frequent Inbox action.
  • There is no filter for the notification reason. "Review requested" and "Mentioned" are the items that need you; in the dev profile, 123 of the 180 unread items are "subscribed", against 27 review requests and 18 mentions.
  • Repository filters are fixed-width chips (178 px) in a horizontal scroller, so most names are truncated (InboxView.tsx:93). With 30 repositories, you scroll sideways to find one.
  • The ▶ launch button is an icon without a label, and "+ Add" only appears when the composer is open. As a result, the same row has a different number of controls depending on the state.
  • In the preview pane, "Close" wraps to its own line, and HTML in comments (for example <h3> from bots) is shown as raw text.
Suggestion. Reason chips with counts (Review requested · Mentioned · Assigned · Subscribed · All), the existing "Unread only" toggle, and one Repository ▾ searchable popover. Each row shows ✓ Done and ▶ Launch. Unsubscribe and Unread stay in the preview pane. After Done, the selection moves to the next row.
Sketch · InboxClick a reason chip or ✓ Done.

7 · Never show an empty main pane when something is waiting

Medium · The Agents page opens with "Pick a session on the left, or launch a new one." (agents/AgentsView.tsx:213) even when 5 sessions wait for you. The Inbox opens with no selection, and its preview pane only appears after a click. Each visit costs one extra click, and the eye must move to the list first.
Suggestion. When nothing is selected, open the first Needs you session (or the first unread review request in the Inbox). After Archive, Done or Send, open the next item in the same group: Archive becomes "Archive and next". When nothing waits, show a short dashboard in the pane: Running (live), Next scheduled launch, Quota, and the Launch button.

8 · Status bar: signals only

Low · The bar shows each harness name and version, two meters with percent and reset time per harness, GitHub core and GraphQL remaining calls, the Launchpad commit, a Terminal button, the dev label, and running/done counts that the sidebar already shows (app/StatusBar.tsx:89). It wraps to 2 rows at 1280 px. Versions and rate limits are useful only when something is wrong.
Suggestion. Keep one compact meter pair per harness that has quotas, without versions. Show a warning token only when needed: "Codex updating", "OpenCode not found", "quota reading 40 min old", "GitHub 312 calls left". Put everything else in a Details popover (versions, commit, rate limits). Keep the Terminal button and the connection warning.

9 · PR page: show the agent's draft first, and make Merge primary only when it can work

Medium
  • "Merge pull request" is a full-width filled teal button, as strong as Launch, even when the panel says "mergeable · blocked" (github/ItemView.tsx:424). The two-step confirmation is good. The visual weight is the problem.
  • Labels and reviewers are free-text fields ("Labels, separated by commas", ItemView.tsx:288), which causes typos and requires you to remember the names.
  • The comment/review box (about 180 px, ItemView.tsx:684) is fixed on every tab, including Files changed, where it takes space from the diff.
  • The top bar breadcrumb is empty on this route (it is set only for Projects and Settings).
Suggestion. A banner under the title on every tab: "Agent draft: Request changes · 3 comments · Review & post". Show Merge as secondary, with the reason ("Blocked: 1 review required"), until GitHub reports the PR as mergeable. Collapse the comment box to a one-line field that grows when focused. Use pickers filled from the cached repo labels and the people who recently reviewed in the repo. Breadcrumb: hub-client / Pull requests / #5102.

11 · Project page: compact, and selection that explains itself

Low · "Running agents · 0" renders a full bordered card (projects/ProjectPage.tsx:60). PR and issue rows are 76 px tall, each with a "GitHub" button (github/RepoItems.tsx:27). The row checkboxes add the item to a launch, but nothing says so until you select one. Worktrees show the path but not the session or pre-draft that owns them.
Suggestion. Header with stat chips (2 running · 1 waiting · 1 pre-draft). Empty sections become one muted line. 12 · Trace: less system noise

Low · In a session where the cost limit was changed a few times, 7 full-width notice lines ("Cost limit set to $0.10 ($0.07 reported so far).", "Cost limit removed.", …) take more space than the conversation. The first user bubble includes the injected skill instructions (the long "Agent-written GitHub comments…" paragraph), so every trace starts with the same block of text. The row badge says "Done 16 h" while the trace says "Turn finished · 7 d ago" (status time compared with turn time).
Suggestion. Fold consecutive notices into one line: "4 cost limit changes · now $0.02 (limit reached) ▸". Show the text you typed in the bubble and fold the appended presets/instructions under "+ Launchpad instructions (2)". Use the same time in both places, or label them ("status since" compared with "turn ended").

Quick fixes (each under an hour)

  • Git view in non-Git folders: hide the button, or show "This folder is not a Git repository" instead of the raw fatal: output (agents/GitPanel.tsx:26).
  • Files from a session: open the code viewer with a "← Back to session" link in the top bar, or as a session tab.
  • Pre-draft with a missing project: "Error: project not found" on an empty page. Show the record, explain it, and add Discard.
  • Breadcrumbs: the top bar is empty on PR, issue and pre-draft routes. On Inbox and Agents, it repeats the page title; drop it there.
  • Workspace buttons: each workspace has its own "new window" icon in the top bar. Use one "Open in new window ▾" menu, so the top bar has fewer controls.
  • Composer Context hint: "type @ or # in the prompt, use the buttons, or add lines from the code viewer" takes 2 lines on every launch. Move it into the placeholder of the prompt.
  • Summary "Next steps": "Schedule follow-up" is always shown, even when there is a real next step. Show it after the real steps, as a small link.
  • Inbox preview: render GitHub HTML for comments, as the PR page already does, instead of showing raw <h3> text.
  • Message box: "Attach images · Drop images here or paste into the message box" uses a full line above every message box. Use a paperclip button inside the box and show the drop hint only while dragging.
  • Project list: the "Add a description" placeholder is shown in italics for every project. Show it on hover of an empty description only, or in the edit mode.
  • Settings save bar: Revert/Save are per card and look disabled until you change something. A sticky "Unsaved changes · Save · Revert" bar at the bottom is easier to notice.
  • Status badges: "Stopped" uses a dashed border, "In terminal" a solid one, and "Done" a filled color. Use one shape for every badge and only change the color and icon.
