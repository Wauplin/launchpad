01 / Product direction

A workbench, with a clear foreground task.

Keep Inbox, Agents and Projects as the primary destinations. Keep Launch visible everywhere. Use project pages to connect code, agents and local PRs; use each detail screen for one active job. A new dashboard, command palette or customizable pane system would add another place to look.

Keep

The foundations that work

Local cached content, explicit GitHub publication, one agent panel, fixed-height virtualized lists, visible workspace buttons, retained composer drafts, exact prompt preview and truthful session states.

Elevate

The daily actions

Launch from current context. Answer the waiting question. Read the last answer. Review changes. Triage a selected notification. Open a local agent draft before publishing it.

Fold

The occasional controls

Scheduling, raw prompt preview, full run facts, environment settings, PR administration and shell utilities. Closed sections must show active values and exception badges.

Rule of thumb: one primary task action per active region, a small set of direct supporting actions, then named disclosure. Keep safety-critical state, spending exceptions and publication destinations visible. “Less bloated” means fewer simultaneous choices, not fewer capabilities.

Recommendations are heuristic judgments, not measured user preferences. P1 means address early because it affects a core task, trust or recoverability; P2 means a useful refinement. There are no claims of emergency defects or measured speed gains.

P1Layout / 01

Give the active task enough room

Observed. The shell keeps a 200 px sidebar, the Agents view a 280 px list, and the launch drawer another 440 px. At the default 120% zoom, a 1440 px window leaves only about 336 physical pixels for the session when Launch is open. At 1280 px this falls to about 176 px. This follows directly from the fixed widths; the browser walkthrough confirms the compression.

Change. Use the docked composer only when the main task retains at least 560 CSS px. Below that, show it as a right overlay with a visible Back to session button and a collapsible context-selection mode. Allow a visible Collapse navigation control and a Sessions button to reclaim list width. Keep drafts when switching presentations.

Keep in mind. Overlay launch interrupts side-by-side reading. Retain docked context collection on wide windows; choose presentation from available width after zoom, not device width alone.

Acceptance check & code evidence

At 1280 × 800 and 150% zoom, prompt, target, billing summary and Launch remain accessible. At 1440 × 900 and 120%, the session message remains readable while adding context.

P1Launch / 02

Make the simple launch look simple

Observed. The drawer exposes harnesses and all variants, destination, prompt, context history, context types, presets, model, effort, cost, Repeat, Start conditions and exact prompt preview in one scrolling surface. The stable footer is a good foundation, but rare controls consume attention on every launch.

Change. Keep Project + Run in, Prompt, attached Context, a compact editable harness/model line and a truthful billing summary visible. Fold Presets, Scheduling and Exact prompt into labeled disclosures. Show counts and non-default values in closed headers; automatically open a section with validation errors. Put billing exceptions next to Launch.

Keep in mind. One extra click for occasional settings is acceptable; never hide an active delayed start, PAYG billing, paid override or cost limit behind an unmarked section.

Acceptance check & code evidence

Launch a prompt using the current defaults without scrolling the form. Reopen a draft and identify every active preset, context attachment and scheduling condition before launching.

P1Sessions / 03

Give the session header a hierarchy

Observed. Summary/Trace, Stop, harness TUI, shell Terminal, Files, Add trace as context, Git, Editor, Archive and Close panel share the action row, while model and billing add more controls above it. Similar button treatments make frequent and rare actions compete.

Change. Keep Summary / Trace / Changes as the main view strip, with state-specific Stop or Resume, Files and a labeled More actions button. Move Editor, shell, harness TUI, trace export/context and Archive into named groups there. Keep paid-usage and cost-limit exceptions visible. Close panel stays separate at the title edge.

Keep in mind. Terminal-heavy users may prefer its direct button. Keep it direct when In terminal, rather than adding configurable toolbars or user-defined layouts.

Acceptance check & code evidence

Find Stop immediately during Running, Resume during Interrupted, and Review changes after Done. Archive and Close panel cannot be confused. Every moved action is accessible in at most two clicks.

P1Sessions / 04

Put the outcome before run accounting

Observed. Summary is already the default on a non-running panel load, and preserves the exact final markdown message. However it renders a potentially long Run block, then the first prompt, then the final message and finally Next steps. Model, billing, folder and command details can push the outcome below the fold.

Change. Use state band → exact last/final message → fact-based next actions → collapsed Run details and Original task. For an unanswered question, show the question first. For a failure with no message, show the recorded failure and Resume. Keep Copy and Show full message.

Keep in mind. Do not generate a second AI summary or infer success from text. Task context remains one click away; incomplete messages must stay labeled Last agent message.

Acceptance check & code evidence

A typical completed session shows its answer and Review changes in the first screen. An unfinished session shows its status and Resume before metadata.

P1Agents / 05

Surface attention without merging states

Observed. Cron and Scheduled precede Running; Done appears after quota, stopped, interrupted, failed and terminal groups. Waiting sessions with an open question use a Question badge but still belong to the Done predicate. Ten nonempty groups can bury the agent needing an answer.

Change. Add a small Needs attention filter beside Pinned, with a textual count and reason per row. Derive it from recorded open questions, failures and quota pauses requiring attention. Keep the existing groups and predicates. Add compact Go to question / Go to result links when opening a waiting session.

Keep in mind. Attention is an additional view, not a new lifecycle state. Normal quota waiting should not repeatedly signal urgent intervention; keep schedules and cron separate.

Acceptance check & code evidence

With 30 sessions and several schedules, locate the unanswered question in two clicks. Sidebar Running/Done counts and dependency behavior stay identical.

P1Billing / 07

Make the actual protection model obvious

Observed. Subscription protection, optional paid usage, native provider billing, PAYG variants and reported USD limits are different mechanisms. Cost-limit copy says the running turn stops at the limit, while the editor correctly explains that Claude reports cost at the end of each turn. That stronger launch copy can imply a hard cap.

Change. Use a persistent compact line: Subscription only · best effort, Paid usage on, or PAYG · reported-cost limit $X. Explain No hard spending cap when editing limits and before launching PAYG. Show unsupported protection from adapter capabilities. Keep Use subscription only visible on paid sessions. Change the launch cost copy to Stops best effort when reported cost reaches the limit; charges may exceed it.

Keep in mind. Condense ordinary guidance, never spending exceptions. Avoid a new billing dashboard: link the compact line to the existing editor and quota details.

Acceptance check & code evidence

For Claude, Codex and OpenCode, explain what is monitored, when usage is reported and whether spending can exceed the limit without reading Settings. No recommendation changes enforcement or paid defaults.

P2Navigation / 08

Show scope where it changes the result

Observed. Workspace buttons are visible and per-window, which is valuable. Inbox also has workspace repos / All repos and repository chips; Projects and Agents have different local filters. The same screen can therefore have global workspace scope plus a local exception.

Change. Retain all workspace buttons and their separate New window controls. Use one short scope caption in list headers, such as Core workspace · 4 projects or All repos · overrides workspace filter. Give local filter chips an explicit Clear filters action. Do not add another navigation tier.

Keep in mind. The top bar will still wrap with many workspaces; this is preferable to hiding owner-required one-click access. Shorten breadcrumbs and reduce spacing before considering a product-rule change.

Acceptance check & code evidence

After switching workspaces with All repos active, predict what Inbox includes and understand why its unread count differs from workspace-only agents.

Observed. General and Harnesses use page-local draft state with Save/Revert buttons. Navigating to another route unmounts that draft. Workspaces, in contrast, saves checkbox changes immediately. These different save models are not obvious from the shared Settings navigation.

Change. Show Unsaved changes next to a sticky Save/Revert bar and keep drafts while navigating between Settings pages, or use a visible save/discard prompt before leaving. Label workspace membership as Saved automatically. Mask likely secret environment values by default with a Show value button.

Keep in mind. Masking is a visual privacy measure, not secret storage. Retain stable variant IDs and make deletion consequences visible before saving; no general configuration migration system is needed.

Some views collapse data-not-yet-loaded into missing or empty: ProjectPage returns This project is not registered when useProject returns null; SessionPane says the session no longer exists; Agents initially treats an empty query result as no sessions. Settings shows Loading if the config query fails.

Change. Have query-backed views handle initial loading, recoverable error with Retry, true empty and confirmed missing separately. Preserve existing cached content on background errors and show whether it is stale. Put persistent failures next to the operation; reserve timed toasts for successful transient feedback.

Keep in mind. Do not add skeleton animation to every cached screen. A small state component and visible Retry are enough; keep network refresh separate from GitHub publication success.

Acceptance check & code evidence

With a disconnected daemon, Settings displays an error and Retry rather than endless Loading. Slow initial project/session loads never claim the object was deleted.

Build accessibility into the shared controls

Observed. Popover is an absolute div with outside-click and Escape listeners, with no shared focus return, collision handling or popup semantics. Several icons rely on title alone; tree/search fields rely on placeholder; find toggles lack aria-pressed; toasts have no live-region semantics.

Change. Define accessible popup triggers with expanded/controls state and appropriate semantics, viewport-aware placement and focus restoration. P2Scheduling / 28

Describe automation in ordinary task language

Observed. Repeat and Start conditions are powerful and already expose AND behavior and native cron syntax. They live in the ordinary launch form; scheduling and same-session follow-ups can be confused because one creates agents and the other sends a message to an existing one.

Change. Fold automation under Schedule · Now / Once later / Repeat, retaining visible non-default summaries. Use Continue this session later for follow-ups and Start a new agent each run for cron. Display local timezone, next run, all required conditions, and skipped/needs-attention outcomes in plain language. Keep Cancel/Pause direct on the corresponding detail.

Keep in mind. Do not invent OR conditions, catch-up behavior, automatic retries or a calendar planner. Human-readable presets should continue to use the existing parser and next-run query.

Schedule one launch and one follow-up and predict which creates a new session. Understand why a cron was skipped and whether quota reset alone will authorize a launch.

07 / Method & limitations

Grounded in this codebase.

This is a heuristic product review, informed by source inspection and a limited live walkthrough of the dev app. It is not a user study or a cross-platform certification. Recommendations are explicitly separated from observed implementation.

Source coverage

Shell, workspace switching, sidebar and status; launch/composer, presets, context, scheduling and cron; session groups, summary, trace, questions and message box; projects and worktrees; inbox; issues/PR controls, conversation, diff and threads; local PRs and suggestions; code tree/search/preview; terminals; settings and variants; shared popovers, toasts, styles and state predicates.

Read Architecture and product rules before proposing hierarchy changes. Generated types and infrastructure were not treated as UX findings.

Checks performed

Built the current UI with pnpm build (including TypeScript checking), compiled and ran the dev daemon, and used real-time Chrome automation against the source UI. Inspected agent list, an idle session, launch drawer at 1440 / 1280 / 800 px, and settings. Captures remain local.

No new agent turns, terminals, schedules, suggestions or GitHub publications were created for the walkthrough. The production daemon was not restarted.

Limits of the evidence

GitHub mutations, real posting/merge, harness handoff and billing enforcement were inspected in code, not executed as UX checks. Most uncommon states were reviewed from rendering logic. Chrome results do not establish WebKitGTK, macOS or Windows behavior.
